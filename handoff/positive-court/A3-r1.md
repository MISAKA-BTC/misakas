## Implemented responsibilities

`node::positive_panel::TirPanelBuilder` implements A0 `PanelBuilder` directly. `PanelAdmission` authenticates the signed `MinerResultCommit` against separately resolved rooted registration/job/input. It applies the annex field mapping, shared selector, coverage-plan derivation, provenance ID and both wrapper budgets. An independent replay uses a fresh ordinary greedy runner and creates a private `TirCaptureV1`. Bounded restore retains the exact expected witness identity and reconstructs source identity without trusting a saved checker cursor or pass flag. Prepared evidence reuses the dense step tree and builds existing G14 cone/trace material in shared `tir::ExactPart` and `EvidenceFrame` framing.

`remote::positive_panel::SignedPanelWitnessR1` uses A0's witness signature domain through the existing local identity signer. Each part also uses the common `EVIDENCE_SIGN_CONTEXT` and canonical `EvidenceFrame::id()`. Batch intake accepts detached signed packets, verifies the ORIGINAL author before touching A1, and calls the actual `NodeChecker` port. Relay takeover retains the exact original signature and packet. Batch byte limits include the extra 4,627-byte signature per frame. `CoverageDescriptor.max_part_bytes` continues to denote the unsigned full frame (284-byte outer + 16-byte inner + cone/trace); native carrier/transaction costs remain additional.

`remote::positive_panel_sources::PanelSourceCacheR1` uses actual A2 `miner::positive_v2::MinerResponderV2` and A0 `MinerSource`, with a passed `CanonicalDataDutyV2`. It authenticates existing G14 artifact inventory and prompt openings, reauthorizes the current duty after I/O, and keeps only bounded local material. Provider fallback and shared service quotas remain in A2; no second service ledger, 4-KiB source tree, receipt-completion flag or native wire tag is created. Cache transfers reauthenticate data and normalize hidden allocation capacity. Complete inventory pieces rebuild the existing PALWTIR1 format; actual class/inventory roots are checked before Panel replay. Flat and Merkle prompts are reconstructed under their original commitments.

The initial supported profile is a **newly registered all-node-commit i32 tiled fixed-length greedy TIR**, with lowest-index tie selection. Existing registered programs are never changed/reinterpreted as that profile. Sparse, wide, stochastic and checkpoint-reuse profiles require explicit checker support; old prototype wide tests are not r1 qualification evidence.

## Native boundaries and activation

A4 must resolve current rooted result/class/job, original author and drawn qualification, current source duty and branch/view, resource reservations, deadlines, native carrier limits and authenticated intake **before** using these APIs for candidate attribution. An authenticated frame proves its author only. A1 checked terminal facts do not themselves produce native guilt, payment or consensus credit. A5 applies the current rooted Gate C/accounting predicate; A6 supplies atomic persistence/reorg/IBD and restoration of all source/attempt/funding budgets. A7's full native/multi-process acceptance remains separate; the r1 acceptance logs here are process-local role tests.

No public activation setting was changed; both new Panel features remain opt-in and default off. No cryptographic computation proof, model review, model-tier change, automatic success stub or copied native coin/accounting engine was introduced. Real LLM cost/profile qualification remains unmeasured.
