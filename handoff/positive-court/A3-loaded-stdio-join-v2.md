# A3 actual Loaded/CPU stdio child join — test-only V2

Status: source-only, UNRUN. A0 authorized the new test-only manifest target; Cargo/rustc remain HOLD. No cache/target directory or production registry/SDK hook is added.

`loaded-wide-process-v2` is a `harness=false`, `required-features=[node]` integration target. Its custom main and actual child run on OS main stacks. This is not a Rust libtest worker/default-stack pass and is not added to the separately proposed59 libtest cases. The ordinary libtest preamble/footer cannot be used as Hello2 protocol bytes; this target has no such output. A future authorized run uses no libtest flags.

Parent fixes independent literal class/program/weights/context before creating an undeclared-layout PALWTIR1 file. Both parent and child separately load the actual regular file through Loaded. Child opens the artifact path exactly once, retains that File through header/Source/compile/native-value loading, then serves ordinary CPU through real stdin/stdout. The parent owns the actual Child through WideCellProcessV2 and mandatory concrete Unix absolute-deadline adapters. No canned shell peer, socket substitution, public raw plan, V1 fallback or stdout-junk skipping is used.

Two real Open/Step/Close cycles compute committed I8 endpoints, full-bit Idx values and i64 MIN/MAX logits. The source/schema are explicit wide V2. Independently calculated request/response frame sizes, cumulative messages/steps/read/write/exported bytes, prepaid Open-build work and total work must match; Close/Open never resets counters. The class registration tokenizer18, actual job tokenizer0, original max context16 and undeclared layout remain literal. This synthetic original context is defined before file creation; no real model is shrunk.

Child input is a `Take` cap on the independently calculated complete request stream. It consumes the actual final Close before reporting bounded EOF, so the existing server can return and the Loaded guard can drop normally. After that, child publishes a fixed256-byte completion record atomically, containing profile, actual file/load/serve flags, startup/session charges, original metadata and released-guard status. Parent inspects completion BEFORE dropping/terminating its process owner, then checks that that owner reaped the specific positive direct-child PID. A separate fixed8-byte PID record and all control reads have a4096-byte cap. Production stderr-null policy stays unchanged; no fd2/pre_exec manipulation is introduced. Cleanup never signals a PID unless a specific-child wait reports it still live; descendants and bounded OS kill/wait scheduling are not guaranteed.

The final key=value marker `A3_LOADED_PROCESS_V2_PASS` exists only after every endpoint, profile, byte/work/usage, guard and reap assertion. It includes `stack=os-main`, actual_file/loaded/cpu_i64_endpoints, cycles/client_steps/server_steps, params_read, child_guard_released and reaped. Unknown Source profile or platform exits77 and emits no PASS marker. Missing, malformed, skipped or incomplete markers are failures, not supported-profile success. Future validation records the actual source/binary hash, Cargo profile, exit code, raw output and marker fields independently from libtest summaries.

Inputs deliberately require an EXISTING PalwTirStepBindingV1 and opaque verified V2 binding, including trace/step/execution commitments. Fixture roots establish synthetic data association only. This test does not implement trace-free first-Miner startup, a new NativeResult/assignment, trained-model registration, native permission or an accepted claim/Court/payment/recovery chain. It does not replace old mandatory bindings with zero roots. Ordinary CPU endpoint comparison is test evidence, not computational certification.

Main inspected all parent/child/record/PID/budget code and the manifest TOML. Independent review is recorded separately. Rustfmt, TOML parse and patch applicability are source checks only; no process, compiler, Clippy, allocator measurement, full CPU/RSS or OS-latency result is claimed.
