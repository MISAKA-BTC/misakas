# Reservation-owned terminal evidence — implementation in progress

This source adds dormant public-filer objects 162/163. A declaration authenticates claim, reserver, the existing reservation's accepted DAA, accused, offence kind, original evidence digest, exact length, per-part digests and the whole-prompt recomputation it buys. Admission fixes the deadline to the live reservation's hard deadline; declarations cannot replace each other or take another verifier's row. Intermediate parts are hashed but never interpreted as evidence. Completion checks the original evidence digest and the normal objective court before the existing conviction and reporter accounting consume it.

A separate rooted table, optional snapshot tail 0xF2 and delta 203 hold declarations. Delta 205 journals each intermediate part rather than writing a complete copy of all previously received bytes on every arrival. Expired/released/settled reservations clean their rows. The original evidence identity is retained for reporter commit–reveal. The transport uses at most 32 parts of 90,000 bytes, further limited by the block-resolved court byte ceiling and the remaining existing reservation window. It uses no certification-lane groups. Maximum transport capacity is a bound, not proof that every admitted profile's terminal evidence fits.

Existing direct court APIs preserve the 100,000-byte ceiling. Explicit budget entrypoints admit larger evidence only under the public-filer session rule and within the court/transport budget. The constraint, IR and batch receipt fences still apply to the assembled proof. A completing carrier spends the existing court-adjudication slot and the same heavy-prompt budget as a direct object. The declaration pays the grading rent and any declared whole-prompt rent; before court execution, the cheap heavy charge must fit that paid declaration.

Production `cargo check -p kaspa-consensus-core --lib --locked` and `cargo check -p kaspad --lib --locked` passed in the initial source round; node check took 45.39 seconds. These are compile checks, not execution evidence. Five transport primitive tests and two fold tests are present but not yet run. The fold fixture uses the existing synthetic licensed core state and signature-sized placeholder manifests, so even a passing fold test does not establish normal mempool signatures or actual service behavior. Wire pins require reconciliation after test build.

Remaining item 2 work includes the native terminal progress reader, automatic public-filer split/schedule/restart continuation, preflight against the same owned terminal court, large job/pin/renderings proof construction, ordinary near-mass-limit hostile/service tests, profile/admission alignment for worst evidence, cumulative deadline/session/carriage/RAM/economic bounds, and the full G14 audit. No activation guard is removed, no active profile is dropped, and ADR-0177 D7 remains unchanged. Full G14 is unfinished.
