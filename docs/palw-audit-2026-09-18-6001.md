# PALW DAA 6,000 / 6,001 pre-arming security audit — 2026-09-18

Tree: `feat/palw-exec-lane-and-validator-retirement` @ `c3a70d55` (fingerprint `a8f99dac…`).
Read-only pass. Two auditors (Agent A: consensus / economics / lottery / W / activation; Agent B:
registry / panel / readiness / liveness / DoS), with cross-component analysis, reorg analysis,
reproduction and severity by the integrator. Verification V2 (`palw_verification_v2`, 6,100) is
outside the 6,001 bundle and is not part of the active security assumption.

## 1. Executive summary

**NOT SAFE TO ARM AT 6001.** Two Critical and six High findings are reachable at the flag day. One
Critical is not a theory: the devnet drill with all five fences armed reproduced it on an eight-node
chain — every block the model class produced was disqualified by all eight nodes, 15 times each,
and the class never opened a claim while the base class reached 172 accepted / 74 Final.

The two Criticals share a shape the release process should note: **a rule the fence retires is still
read by a neighbouring rule**. The class target stops pricing the draw but still prices `pwu`
(C-2); the registry's work stops coming from the chain and starts coming from a node-local store
(C-1). Both are one-file, few-line fixes, and the same patch for C-2 closes the fork-choice
inflation Agent A found independently.

The 6,000 boundary itself is clean: at 5,999 and 6,000 no PALW upgrade rule is active, the held
regime and the deep audit fire alone at 6,000, and an old binary is refused from 6,000 by the fork
id. The monetary structure is sound — the escrow is withheld before it is paid, the split is exact,
and no path mints twice. What fails is the model lane's liveness and two rules that still read
retired inputs.

## 2. Critical findings

### C-1 — the registry fold's works map is node-local, and at 6,001 it starts deciding the state root and admission
*(Agent A A-01, independently confirmed by the integrator as O-02)*

* **Where**: `consensus/src/pipeline/virtual_processor/processor.rs:7869` (`palw_known_model_works_v1`)
  → `:7947` (`palw_model_registry_fold_at`), read by
  `consensus/core/src/palw_state_v2.rs:8035` (`model_class_work`), `:8425` (`step_model_registry`)
  and `:8352` (`check_class_admits_claim`'s `ClassNotAdmitting{no row}` arm).
* **Why it is node-local**: the map's last source is `self.palw_class_carriage_store.read().get(class_id)`
  — a RocksDB store written at block acceptance where a failure is a `warn!` and the block is still
  accepted (`processor.rs:5289`), synced **best-effort** at the pruning point
  (`protocol/flows/src/ibd/flow.rs` ~2565-2600: a peer that serves none produces a `debug!`, and
  nothing requires a declaration for every rowless class). It is also enumerated from
  `load_tip_cached` (the node's own tip, not the block being folded), memoised for the process
  lifetime, and has a `#[cfg(target_arch = "wasm32")]` arm that returns `None`.
* **Preconditions**: a class in `state.classes` with no lifecycle row. Rows open from the object for
  registrations accepted past the fence, so the exposed set is classes registered post-genesis and
  **before** the registry fence — plus any class whose store write failed on some node. Registration
  is permissionless and not gated by the registry fence, so an attacker can create the precondition
  for the price of one registration before 6,001.
* **Impact**: two honest nodes fold different rooted state for the same block — one writes the
  `model_lifecycles` row and a `claim_economics` snapshot (and pays `min(escrow, attempted × rate)`),
  the other writes neither (and pays the full escrow) — and they disagree about whether an attempt is
  admissible. Chain split, no attacker required once the precondition exists. A single node can also
  disagree with itself across a reorg, because the store mutates over time: the
  apply → reorg → replay identity fails.
* **Reproduction**: two processors with identical params and chain, the carriage store populated on
  one only; fold the same block past 6,001 and compare `state_root()` and
  `check_class_admits_claim`. They differ.
* **Minimal fix**: make the works map a function of the chain and the build only — drop the carriage
  store, the `load_tip_cached` enumeration and the `target_arch` arm from the fold input. A pre-fence
  class then gets no row on every node alike (which the code's own documentation already describes)
  and obtains one by re-registering past the fence; post-fence registrations are unaffected.
* **Regression test**: `the_registry_fold_is_a_function_of_the_chain_and_the_build_not_of_a_local_store`.

### C-2 — past the work target the chain prices `pwu` from a registrant-declared, never-re-priced class target: the model lane is dead for honest producers and fork-choice weight is free for an attacker
*(integrator O-01, live-reproduced; Agent A A-02 found the attack half independently)*

* **Where**: `consensus/core/src/palw_admission_v2.rs:346-356` — the `PalwPwuRuleV2::DerivedV1` arm
  reads `state.class_target(&attempt.class_id)` and demands `attempt.pwu == palw_pwu_v1(target, pwu_per_inference)`.
  The producer derives the same number from the new ticket
  (`consensus/core/src/palw_producer_v2.rs:238-249`, used at `kaspad/src/palw_producer.rs:966`), and
  the lottery itself already uses the new ticket (`check_palw_class_lottery_v4`). Nothing re-prices a
  class target past the fence: `apply_class_retargets` skips non-base classes and
  `step_model_registry` returns before its ADR-0076 seating price.
* **Impact (i), liveness — reproduced**: every attempt block of a `DerivedV1` class (which is what
  `palw_genesis_v2.rs:498` gives every genesis class, i.e. testnet-11's A16 and QWEN36) is
  disqualified from the virtual chain. Drill evidence, commit `25719ec8`, all five fences at 20/40:
  `claimed pwu 19891632 is not the derived 1843291232 — pwu is chain state, not a miner input`,
  **15 occurrences on each of 8 nodes**; node-3 produced 9 blocks for the class and the class census
  stayed at `accepted 0 / final 0` while the base class reached `172 / 74`.
  Saved at `/root/drill-adr0135/pwu-bug-evidence.txt` and `run17-pwu-bug-0412/`.
* **Impact (ii), consensus takeover**: an attacker registers a class with `initial_target = 1`
  (only `0` is refused) and crafts attempts with `pwu = palw_pwu_v1(1, counted) = u64::MAX`, which is
  exactly what the chain's check demands. Each **accepted** claim credits
  `bounded_immature += β·pwu/1000` before any verification, and each Final credits
  `safe_weight += pwu`; both feed `PalwCandidateOrderV1`, i.e. fork choice. The collateral at risk
  does not scale: `palw_exposure_pwu_v1` reserves `pwu_per_inference` for `DerivedV1`, not the
  claimed pwu. A class registered permissionlessly holds a share ≥ 1‰, so it bears weight.
* **Minimal fix (closes both halves)**: one spelling of the rule. Add
  `palw_effective_class_target_v1(state, state_params, class_id, lottery_floor)` — the legacy
  `state.class_target` below the fence or for the base class, otherwise
  `palw_work_ticket_target_v1(row.work.economic_ccu_per_claim, floor)` with `ClassWorkUnknown` on a
  missing row — and call it from the `DerivedV1` pwu derivation, from
  `check_palw_class_lottery_v4` and from `palw_producer_facts_v2`. The declared target then stops
  reaching pwu past the fence, and the producer and the chain agree by construction.
* **Regression test**: `adr0137_past_the_fence_the_chain_derives_the_same_pwu_the_producer_claims`
  plus `a_declared_class_target_buys_no_weight_past_the_work_target`, and the drill's phase 2
  reaching Final.

## 4. Medium findings

* **A-04** — the Final price is computed from the two inputs the same flag day retires
  (`palw_expected_attempts_q32_v1(class_target)` and the header's `bits`), so a claim is not priced
  for the compute it ran and the multiplier is registrant-settable. Fix: past the single lottery
  price from `palw_expected_forwards_q32_v1(ccu, max(W₀, W))` and a network draw of one.
* **A-05** — past 6,001 a model class has no per-epoch block cap and `produced_blocks` counts claims
  that never finalize, so W can be pushed up ×4 an epoch (and takes as long to come back), which
  hardens every honest class's ticket. Fix: count the closed epoch's model blocks from `final_work`
  (already in state) rather than from `epoch_counters`.
* **B-06** — `ClassManifestV2.artifact_bytes` has no consensus reader today
  (`artifact_prefetch_spans` and `working_set_bytes` are derived and never read), yet each
  submission rewrites the rooted registry row for a transaction fee. Fix: derive the count from the
  artifact inventory the root already commits to, or accept it once per (class, root).
* **B-07** — an operator identity costs nothing: `BondRegistered` accepts any non-empty
  `operator_pubkey` with no proof of possession, and `operator_id` is the panel's only Sybil
  defence. Fix: make the operator key sign the registration and refuse duplicates.

## 5. Low findings

* **A-06** — a missing header silently prices the network draw at one and that default reaches the
  state root; return `None` and refuse the fold instead.
* **B-08** — a readiness proof may carry an 8 MiB operand, over three times the ruleset's largest
  otherwise-priced object, with no per-block or per-bond cap.

## 6. False positives investigated (not findings)

* The panel payout key colliding with a claim id — 64-byte domain-separated hash, a reserved prefix
  byte only.
* `apply_class_retargets` clearing the epoch counters before `apply_work_target` reads them — nothing
  between the sweeps and the work target writes `epoch_counters`.
* A lifecycle row being removed and re-exposing a class to the node-local works — no caller ever
  writes `None` to `write_model_lifecycle`.
* The claim's economics snapshot being swapped between accept and Final — written once, cleared at
  Final, no other writer.
* `saturating_sub` in the coinbase hiding an over-withholding — it clamps toward withholding, which
  under-issues.
* `palw_work_ticket_target_v1` overflowing — `mul_div_u128` saturates only above `ccu × work > 2^128`,
  far outside any derivable CCU, and the bias is toward MAX.
* A zero payout rate or zero escrow passing silently — `palw_work_floor_v1` returns `u128::MAX`
  (nothing wins) and `validate_palw_v2` refuses `rate_sompi_per_giga == 0`.

## 8. Monetary invariants checked

| invariant | verdict |
|---|---|
| producer + panel + reserve ≤ the escrow of the block that escrowed the claim | holds — `palw_panel_split_permille_v1` sums exactly; `priced_reward ≤ claim.escrowed_reward` |

## 9-13. Attack classes checked

* **Permissionless registry**: 1000 classes, duplicates, near-duplicates, zero-work graphs, enormous
  graphs and metadata, malformed and overflowing dimensions, unsupported opcodes, spoofed
  `artifact_bytes`, root mismatches, zero-byte artifacts, extreme canonical jobs, pathological MoE
  graphs. Result: the graph checks and the `pwu_per_inference == counted leaves` rule hold; the
  economic ones do not (H-5 unreclaimable growth, B-06 inert-but-rooted field, C-2 declared target).
* **Panel / readiness**: proof replay, stale and future spans, cross-class and cross-bond proofs,
  leaf substitution, forged signatures, reuse after a reorg, ready-after-deletion, own-claim judging,
  multi-seat operators, bond splitting, collateral reuse, conflicting and withheld receipts, false
  `Incapable`, `NoCapablePanel` abuse, redraw grinding. Result: the signature and window checks hold;
  the possession semantics (H-6), the eligibility mismatch (H-3) and the free operator identity
  (B-07) do not.
* **W / lottery**: CCU ∈ {0, 1, W−1, W, W+1, ≫W}, W ∈ {0, 1, MAX}, target ∈ {0, MAX}, Q32 conversion,
  saturation, the clamp edges, cheap-class and burst-mining manipulation, empty epochs, boundary
  reorgs. Result: the arithmetic is sound and manipulation costs real compute (blocks per second is
  `compute/s ÷ W`, independent of model size); the controller's input is the wrong one (A-05).
* **Reorg / activation**: 5,999 / 6,000 / 6,001 / 6,002 read from the code and pinned by
  `t11_daa_6000_is_the_compatibility_boundary_and_6001_the_one_palw_upgrade_flag_day`; the old binary
  is refused from 6,000; every bare DAA constant in consensus code was grepped and the one that was
  outside a fence (`window_challenge_at`) is now `palw_short_challenge_window`. Remaining activation
  defect: H-1 (the pruning proof) and H-2 (the grace).
* **Resource / DoS**: zero-PoW attempt headers past the single lottery (Medium — testnet-11's `bits`
  already sits at difficulty 1.0, and the receipt lane has had an unconditional pass since ADR-0083,
  but on a network with meaningful `bits` this removes a real bound), the 8 MiB readiness operand
  (B-08), the per-block payout drain of 8, and the node-side artifact memory budget (H-4).

## 14. Missing test coverage

* No test folds one block through two processors whose carriage stores differ (C-1).
* No test asserts the producer's `facts.pwu` equals the chain's derived pwu past the fence (C-2).
* No test covers a pre-fence post-genesis registration crossing the registry fence.
* No test validates a pruning proof containing post-fence attempt headers (H-1).
* No test asserts a class admits claims during the registry's activation grace with zero readiness

* `every_primary_datum_moves_the_root` does not perturb `work_target`, `claim_economics`,
  `model_lifecycles` or `seat_readiness`.

## 15. DAA 6,001 release blockers

C-1, C-2, H-1, H-2, H-3, H-4, H-5. H-6 is a documented V1 limitation of the possession proof and is
a design decision for the operator rather than a code defect, but it is what the 6,001 economy leans
on. The Mediums and Lows are not blockers.

## 16. Residual risks after those fixes

* H-6's possession semantics stay as designed until the proof's width is a function of the artifact
  (ADR-0135 lists it as not built).
* A-05's controller input (blocks, not Finals) stays until it reads `final_work`.
* The zero-PoW attempt header stays a design property of the single lottery; it matters on a network
  with real `bits`, not on testnet-11 at difficulty 1.
* Verification V2 at 6,100 was not audited as an active assumption; it must be audited before its own
  day, and its runtime half (checkpoints, resume) is not built.

## Verdict

**NOT SAFE TO ARM AT 6001** — on the strength of two Critical findings (C-1 consensus split from a
node-local fold, C-2 the retired class target still pricing `pwu`, reproduced live) and six High
findings, all reachable at the flag day.
