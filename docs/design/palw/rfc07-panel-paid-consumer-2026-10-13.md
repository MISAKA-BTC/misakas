# RFC07 native Panel paid consumer — 2026-10-13

## Implemented contract

The existing paid source ledger now has a native Panel consumer. The optional signed kernel inner kind `FundPanelBeaconSourceFeeV2 = 63` uses the existing `palw_beacon_source_fee_v1` fence together with active source and Panel policies. It carries the epoch and exact `BeaconSourceFeeTermsV1`; native consensus derives all target authority. A bare kernel ledger refuses this kind, because it cannot derive the native epoch or authenticate the sponsor bond. Old ModelConformance funding/opt-in kinds 61/62 retain their wire encodings and semantics. No network preset is armed and no approval registry entry is added.

Native consensus freezes optional aux table 112, `PalwPanelSourceFeeAuthorityV2`, with the exact versioned request, existing complete epoch snapshot root (table 111), challenge/Panel/source policies, native liability tail, actual authorization DAA and named sponsor. Tables 108/109/110 retain their old schemas for source target, fee target and cost bounds. The new authority is an optional journaled row rather than a mandatory field in historical carriage/header types. Inner kind 63 is appended in its explicit tag allocation and A2 owner inventory; older nodes cannot decode it. Below the existing fence, the gate handles it as undecodable bytes. An armed private branch therefore requires nodes supporting this inner kind; public activation remains prohibited by the existing validation rules.

The signed sponsor object must bind its own native bond ID, the exact frozen context and clocks, fixed gross fee and capacity. The epoch's actual accepted commitment must be after both source/fee fences. Authorization must occur at or after that commitment and strictly before source seal start. A repeated or substituted authority, unsupported/nonpaid policy, insufficient k capacity, unmeasured/out-of-scope cost tuple, incorrect sponsor or impossible Final/lock deadline is refused. The finite signed source-contract tail is derived by consensus as native challenge window plus twice the native court window. `H = max(source Final + D, epoch deadline + assignment delay + receipt window + native tail)`. Overflow refuses admission. This formula is not a proof of the last possible dependent Panel consumer position: retries, paused receipt clocks, bounded draw queues and sparse canonical DAA can defer existing Panel consumers beyond it. The required absolute versioned consumer expiry/inclusion contract is still open, as explained below. The target retains every assigned work ID as an entropy exclusion after its claim leaves the pending phase.

One transition checkpoints state, writes authority/target/cost rows, and invokes the existing native funding fold with the same admitted signer. That fold strictly debits actual native free collateral into the rooted source escrow. Refused funding restores the checkpoint, including authority rows. There is no accepted target-only half transition. Panel target projection before S is permitted solely for this pre-entropy funding path; the common source seal admission still requires the ordinary seal in `[S, seal_end)`.

The existing paid opt-in, native source R reservation, source collateral, reveal/Final/veto, sparse closing tick, principal refund and pending UTXO payout queue remain the common money consumer. Source Final alone pays nothing. The H+1 tick consumes the once-only source reservation and moves the same R into the recipient's pending payout reservation. Refunded principal creates no income. Ledger, authority, budget and queue rows use the same native delta journal. Native `ChainPanelBeaconHistoryV1::paid_material` now obtains paid v5 material only with a valid Panel sponsor authority; the actual `PanelBeaconProofV3` verifier uses that material.

The SDK exposes `panel_funding_object_from_kernel_rows_v2`, returning the exact unsigned inner-63 sponsor object derived from authenticated epoch inventory and the client's compiled params. It does not sign, assert economic approval, or infer native spendable collateral from a kernel balance. `paid_panel_sources_from_kernel_rows_v2` reconstructs complete ledger/aux roots, validates epoch/authority/cost/funding, rejects assigned work as a source and verifies/derives the same paid v5 beacon. The caller must authenticate the served roots against chain history.

## Absolute consumer horizon remains open

`PermissionlessPanelStateV1::stage_assign` may perform `max_retries + 1` draws. Its receipt clock pauses while native DA/court/default accusations are pending and re-bases after session close. `max_assignments_per_block` also defers canonical due draws. Sparse DAA permits a later block to reach a due queue entry far beyond an arithmetic receipt deadline. The new source contract's H is authenticated, immutable and enforced by its source-money ledger, but existing Panel draw/claim admission does not enforce an absolute matching consumer expiry. It must not be reported as full Panel lifetime liability/retention coverage.

A complete versioned paid Panel consumer contract must bind the final absolute accepted beacon/draw/retry/receipt/claim/material deadline, count every permitted retry and all bounded accusation pauses, and reserve worst-case inclusion/court/retention capacity at enrollment. The native Panel consumer must refuse new use beyond that deadline through a specified terminal result which cannot neutralize a timely open fraud/default demand. Restart/reorg/sparse ticks must preserve that authority and expiry, and the reviewed soundness union must charge every branch/offline choice and admitted subject. A declaration of maximum lifetime or another source fund object cannot reset it. This changes accepted Panel behavior and needs its own versioned policy/consumer migration; the new funding kind does not silently change historical Panel semantics. This work keeps public activation and full security approval closed.
