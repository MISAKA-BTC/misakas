# testnet-12 DAA 14,000 リリース計画(2026-10-15 ユーザー決定)

**決定:** 稼働中の testnet-12 を、`pre` に載っている実装(RFC02・RFC06/07/08/12・G14・RFC-0015〜0019・ADR-0162〜0179)へ更新する。新規 fence は **DAA 14,000** で有効化する(当初案の DAA 12,000 から変更)。

## 進める順序(この順を崩さない)

1. **全部完了:** G14・RFC02・RFC06〜12・RFC-0019 のコード実装を完了し、統合ブランチ `integ/rfc02-rfc06-12-g14` へ集約する。
2. **一括検証:** 生成物の再現性 → cargo check(全段)→ 対象テスト → 影響スイート → clippy。未有効化時に旧ルールと同一であること(t12 の params id・指紋・A-2)を確認する。
3. **実ノード検証・測定:** RFC-0019 までに新しく実装した全経路と、ブロック生成を、ローカル devnet / 校正ネットワークで検証する。複数モデルの同時生成と RED 取り込み、Gate C、300M 閉鎖モデル攻撃試験、分断・再接続・IBD での収束、heartbeat/BASE-0 の継続も含める。測定値(V+ の σ/k、ADR-0176 の Q/B/R/F・予約額・burst、認証の m/k など)を記録し、測定値記録の gate を満たす。
4. **drill:** 出荷するバイナリそのもので、DAA 14,000 の fence をまたぐ drill を行う。fence をまたぐ drill 無しに出荷しない。
5. **承認後に配備:** ユーザー承認の後に、t12 のノード運営者へ配布・更新する。

## 原則

- 測定値の記録が無い仮の値のまま有効化しない(各 fence の measured-value gate)。間に合わない fence は、有効化対象から外して休眠のまま載せる(ユーザーに報告して判断を得る)。
- 有効化前は、旧バイナリと新バイナリが同じブロック・state root・fork choice になること。
- 永続決定: PRINCIPLES §8(計算の暗号学的証明を使わない)、§9(モデル二階層、モデル単位の検証は不採用、claim 単位の検証は全モデルで維持)。DNS-BFT は RFC-0012 方式 (b) で退役し、新しい規則は依存しない。
- 指紋が変わるリリースは origin/main へ fast-forward で push する(既存の運用則)。

## G14 と legacy 経路(2026-10-16 ユーザー決定)

[G14 完全性の監査](g14-completeness-proof-2026-10-16.md)の結論は「f244ed92d の source では、DAA 14,000 の計画で G14 の主張は成り立たない」だった
(報酬を出すのが G14 を満たさない legacy Panel 経路だけ、G-01)。これを受けたユーザー決定:

- **G-01 は (b) で進める。** DAA 14,000 以後に受理する新規 claim について:
  - G14 の公開告発経路が武装されていない種類(family)の claim は、報酬・weight・consensus credit を得ない(carrier の通常 fee のみ)。
  - 正直な seat 1 人でも裁けない Free Prompt の選択・constraint・prefix・tokenizer の job は、受理時に拒否する(G-05)。
  - 経路を検証して武装した種類から、報酬は自動で戻る。
  - fence 前に受理した claim は旧規則のまま決済する。
  - PRINCIPLES §6(7 条件が揃うまで報酬・weight を与えない)と、2026-10-12 の N4 判断(非公開経路は新 fence で新規報酬外)と同じ形である。
- **将来のネットワークでは G14 は genesis から有効になる。** 実装はそれに近い形で進める。
  - G14 に関わる fence は DAA 0 で動くこと。fence 前の履歴・legacy 経路の状態・legacy filer の予約に依存しない。
  - G14 の fence を全て 0 にした試験用 ruleset で、block 0 から次を確かめる:legacy 経路は報酬を出さない、非公開 material の work は報酬を出さない、G14 経路を武装した種類だけが報酬を得る。
- DAA 14,000 で報酬が続くかどうかは、TIR 公開 frame(`palw_tir_public_conviction_v1`、frame 必須化 G-03 を含む)を試験と drill を通して武装できるかで決まる。
  通らなければ t12 の PALW 報酬は、経路を武装できるまで止まる(ユーザー了承済みの帰結)。
- (b) の fence 自体は報酬を外すだけで、経済の測定値を要しない。武装に要る記録は、その試験と node E2E、DAA 14,000 を跨ぐ drill である。

## court の全体容量と Panel 担保(2026-10-16 ユーザー方針)

legacy lane の close-out([監査 付録 D](g14-completeness-proof-2026-10-16.md))で残った 2 件を、ユーザーは**別々の問題として**扱うと決めた。
LG14-A の既存の仕組み(claim 固有の絶対期限、reservation による Final 保留、bond ごとに独立した DA セッション予算)は、どちらでも維持する。

### 1. court の 42 枠(G-07)— 処理容量に基づく予算管理と、枠を占有する時間のコスト化

**課題。** bond ごとの上限だけでは足りない。多数の bond を用意すれば、ネットワーク全体の 42 枠を占有できる。
G14 の要件は「正直な検証者が 1 人でも告発できる」ことである。したがって必要なのはスパム抑止ではなく、**実際に裁定まで到達できる容量の保証**である。
fused leaf は KernelWitness → ShardCourtAccused → held dissection の経路で裁定する。

**構造**
- **court admission:** bond 担保、claim の期限、費用を検査する。
- **処理予算:** ブロックごとの CPU・検証・証拠処理量を、決定論的な cost unit で制限する。
  - 値は、低速なサポート対象ノードで検証時間・メモリ・証拠サイズを測ってから固定する。
  - 実行時の CPU 時間は合意の入力にしない。
  - 測定するまでは仮の値とし、武装を拒否する。
- **時間コスト:** court 費用 = ρ_court × 占有 DAA × 資源重み。
  - 開始時に、最大期間分の担保と料金を確保する。終了時に未使用分を返す。
  - 不正が客観的に立証された正当な告発には、可能な範囲で被告側の slash から費用を補填する。
- **期限付きの決定論的スケジューラ:** 予約中の正当な追及が、期限内に進行できるかを検査する。

**限界と安全側の扱い**
- 予算制限と時間課金だけでは、資金力のある連合による 42 枠の占有を数学的には防げない。
- そこで、正直な検証者の追及を期限内に処理できるかを、待機キューと最悪ケースの処理時間で検証する。
- 処理保証が成立しない場合は、新たな報酬対象 claim の受理量を制限するか、その fused 経路を報酬対象にしない。
- **42 枠の飢餓耐性を実証できるまで、fused leaf 経路を「解決済み」として有効化しない。**
  option (b) では、fused leaf の裁定に依存する claim は、court 容量の fence が武装されるまで「G14 経路あり」と数えない。

### 2. Panel の担保効率(G-13)— 責任担保と新規業務用の資本枠を分離する

**Final+1,000 DAA で担保を無条件に解放する方式へは戻さない。** claim の責任期間がそれより長いと、後から不正が確定しても Valid 署名者に十分な slash を執行できなくなるからである。

既存の `palw_final_lock_full_collateral` を活用し、同じ bond の担保を次の 2 区分に分ける。

| 担保区分 | 役割 | 新規業務の計算 |
|---|---|---|
| Active liability | 審査中・裁定中の claim を保証する(LG14-A の reservation が Final を保留している間を含む) | 業務枠を消費する |
| Resolved liability | Final 後も残る不正追及の責任を保証する | 業務枠からは外せる。総担保からは差し引く |

新しい仕事に使える残余は次のとおり。

R_new = max(0, min(C_work − L_active, C_total − L_active − L_resolved − R_other))

- Resolved liability を新規業務枠から外しても、slash できる総担保からは外さない。外すと、同じ担保を二重に保証へ使うことになる。
- この方向は既存の V02(a) に近い。
- ADR-0160 の aggregate liability や係数 ρ を使って資本効率をさらに上げる場合は、検証を追加する。対象は、複数の claim が同時に不正でも、徴収できる額と凍結処理が整合することである。

### 3. drill の合格条件

| 試験 | 合格条件 |
|---|---|
| 42 枠飽和攻撃 | 連合が全枠を占有しても、独立した検証者が期限内に裁定できる。42 枠を埋めた状態で 43 番目の正直な検証者を投入するだけでなく、**継続的に枠を埋め直す攻撃**も再現する |
| court 処理予算 | 最大負荷でも、ノードの検証時間・資源の上限を超えない |
| 時間料金 | bond を分割しても占有コストを回避できない |
| late conviction | Final+1,000 以降でも、責任期限内なら Valid 署名者を適切に slash できる |
| 担保の再利用 | Active と Resolved の合計責任が、実際の担保を超えない |
| 資本効率 | 担保量 × ロック期間、業務の処理件数、参加できる Panel 数を旧仕様と比べる |
| 再起動・reorg | court の予約、期限、課金、担保の解放結果が一致する |

### 4. 優先順位

1. court の各操作を実測し、ブロック予算を固定する。
2. 時間課金と待機・期限の処理を組み合わせ、連合攻撃の下でも G14 に到達できることを検証する。
3. Panel 側では、既存の full-collateral 区分を使い、責任期限を保ったまま実効処理能力を測る。
