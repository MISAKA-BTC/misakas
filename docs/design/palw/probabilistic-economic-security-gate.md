# PALW 確率・経済安全性ゲート(Probabilistic–Economic Security Gate, PESG)

**Status:** ユーザーの指示(2026-10-10)による release gate。RFC-0007・RFC-0011・RFC-0014・RFC-0015 を横断する。
すべての ActiveRewardable 判定と、報酬・consensus work weight・Panel=0 の fence の武装に先立って成立を要求する。
これは設計・受入仕様であり、実装や測定の完成を意味しない。

すべての試験は休眠 fence の下で行う。ユーザーの承認と独立した安全性レビューなしに、新しい fence を武装しない。
上位前提は [docs/PRINCIPLES.md](../../PRINCIPLES.md)。

## 0. 最終目標(四条件)

1. **全ての報酬対象計算に検証経路がある。** 通常時の全量再実行は要求しない。ただし、攻撃者が不正を置ける場所を検査対象から外さない。
2. **最も検出されにくい不正でも、検出確率の下限が証明されている。** producer と Panel 全員が共謀し、検査位置の偏り、beacon 操作、Sybil、証拠隠蔽を悪用する条件で評価する。
3. **不正が立証されれば、Panel 外の 1 人の検証者が客観的な裁定を完遂できる。** 計算不正は exact court、未開示は DA/default として区別する(G14。codex が担当)。
4. **不正による期待利益が、徴収可能な損失と攻撃費用を考慮すると負になる。** producer・共謀 Panel・関連 bond を一つの経済主体として合算して評価する。

これに加えて、**抑止が破れても被害を有界化する合意規則**(§6)を独立に要求する。
期待利益が負であっても、資金を犠牲にしてでも妨害する攻撃者を排除したことにはならないからである。

## 1. 経済式

| 記号 | 意味 |
| --- | --- |
| `G` | 不正が成功した場合の最大純利益。claim と Panel の報酬、verifier bounty、登録・市場での利益、fork-choice weight、EVM・外部決済への影響を含む |
| `p` | 期限内に検出され、証拠が受理され、実際に処罰される確率の下限 |
| `L` | 処罰されたときの徴収可能な純損失(担保没収・slash)。名目額ではなく実際に徴収できる額とし、自己摘発による 49% の還流を差し引く |
| `C` | 不正を試みるために必ず失う費用(登録料・封印手数料・検査や試行の費用) |

```
E[Π_attack] = (1 − p)·G − p·L − C             合格条件: E[Π_attack] < 0(安全余裕を持たせる)
C を安全側に 0 と置くと:  L > (1 − p)/p · G
```

| 実効 `p` | 必要な `L / G` |
| --- | --- |
| 1% | 99 倍超 |
| 10% | 9 倍超 |
| 50% | 1 倍超 |
| 90% | 約 0.112 倍超 |
| 99% | 約 0.0102 倍超 |

外部ブリッジや市場へ先に持ち出せる利益など、発覚後も回収できない利益は、その最大額を `G` に含める。
上限を導けない `G`、下限を保証できない `p`、実徴収額を確認できない `L` は **UNKNOWN** とし、PASS にしない。

## 2. 確率検証で確認すること

ランダムな 1 区間の抽出検査と、代数的検査(Freivalds 等)は、同じ安全性ではない。

例として、1,024 区間のうち 1 区間だけを改ざんし、1 区間だけを検査する場合を考える。
- 検出確率は 0.0977% にすぎない。
- §1 の式では、利益の約 1,023 倍を超える徴収可能損失が必要になる。
- しかもこれは、検証者が必ず動くと仮定した楽観値である。

| 方式 | 検出可能性 | 判定 |
| --- | --- | --- |
| ランダムな 1 区間だけを検査 | 検査対象外の単一点不正を高確率で見逃す | 監査・異常検知には使える。それだけで全体の安全性は保証しない |
| Freivalds などの代数的検査 | 条件が成立すれば、全行列関係の不正を少数の演算で高確率に検出する | 対応する計算関係ごとに soundness を証明する |
| GKR・sum-check 等 | 集約計算の制約を確率的に検証する | transcript・round・証拠の binding まで含めて証明する |
| exact court | 特定済みの不正箇所を決定論的に判定する | 確率的検出の後の裁定に使う |

AuditOnly の小さなサンプル数を、全 claim を検証したことに読み替えない(RFC-0007 Part V)。

**128-bit の目標は二つに分け、混ぜない。**
- **暗号学的な検査器の健全性 `ε_check ≤ 2^-128`:** 承認済みの検査器を正しく実行したとき、偽の計算が確率的検査を通過する条件付き確率の目標。
- **現実の検出・処罰確率 `p_convict`:** 正直な監視者が期限内に検査し、証拠を通し、処罰が成立する確率。監視者の稼働、DA の取得、通信、提出、裁判、担保回収をすべて含む。

128-bit の検査器があっても、誰も検査しなければ不正は検出されない。「ネットワーク全体で 128-bit 安全」とは宣言しない。

## 3. 試験の 6 系統

| 試験 | 何を確認するか | PASS 条件 |
| --- | --- | --- |
| T1 検証範囲 | 全 kernel・job・input・output・state・boundary・DA に検証関係があるか | 未検査の報酬対象 relation が 1 つでもあれば FAIL |
| T2 確率・暗号 | 最も有利な単一点改ざん、適応的 grinding、seed 選別、反復・相関 | 全 claim の見逃し上限と、必要な独立性を理論的に導出する |
| T3 G14 客観裁定 | producer と Panel 全員が共謀しても、外部 bond が公開材料だけで裁けるか | 不正を局所化して exact conviction、未開示は DA/default |
| T4 経済・担保 | 最大利益、検出率、実徴収額、同時 claim、退出・再利用 | すべての許可攻撃で期待利益が負 |
| T5 監視者インセンティブ | 正直な verifier が通常時の検査費用を回収できるか | 不正がない時期も検査への参加が持続する |
| T6 統合攻撃 | reorg、Final race、Sybil、枠の占有、隠蔽、partition、beacon 操作 | 安全性と経済計算の前提を壊す実経路がない |

T3 の必須条件と処罰の扱い:
- 「Panel 5 人全員が悪意で、正直なのは Panel 外の公開 bond 1 人だけ」という条件を必ず試験する。
- 計算不正があっても、全 Panel を自動では slash しない。各 Panel が実際に署名・保証した scope について、FalseValid などの責任を個別に立証する。
- Panel=0 では、Panel の担保が存在するものとして計算しない(RFC-0014 §8–9、RFC-0015 §8)。

## 4. 各 lane の受入仕様(A〜F)

**基本方針。** 報酬対象の class・kernel・verification plan・task/context ごとに、確率的検査・客観的裁定・経済的抑止を同一の攻撃シナリオで同時に検証する。三つを別々に PASS としない。
producer・Panel 全員・関連 public bond が同一の経済主体として共謀する最悪ケースを必ず含める。

### A. 攻撃者利益の上限(ECON)

各 class/profile と攻撃シナリオについて、次の量を算出する。
- `G_max`:不正成功時の最大純利益
- `L_collected`:producer、責任が立証された Panel、共謀 bond から徴収可能な純損失
- `C_attack`:攻撃に必ず伴う費用
- Exposure:同時 claim 数、再利用される担保、未決済の reward、退出可能になる時点、reorg 後の担保状態
- `p_min`:攻撃者にとって最も有利な戦略に対する、保守的な検出・処罰確率の下限

```
EV(a) = (1 − p_min(a)) × G_max(a) − p_min(a) × L_collected(a) − C_attack(a)
全ての許可攻撃 a で、安全余裕を持って負であること
```

Panel=1、Panel=0、現行の Panel 経路は別々に算出する。

### B. 不正の最適配置と検出確率(検証・soundness)

攻撃者が検査を最もすり抜けやすい場所と方法を探索する。必須の故障は次のとおり。
- **単一点:** 1 要素、1 区間、1 token、最後の token
- **演算:** MatMul、quantization、nonlinear、routing、TopK
- **構造:** encoder、decoder、state、checkpoint、segment 境界
- **偽造:** 別 job の正しい trace の流用、自己整合した偽の trace・root・operand
- **DA:** withholding、部分開示、偽の開示
- **beacon:** seed grinding、beacon の withheld、seal の置換、reorg による再抽選
- **相関:** 同じ seed を使う複数の Panel・watcher による検査の相関

geometry の大きさで方法を分ける。
- **小さな有限 geometry:** 不正の配置とサンプルの選び方を総当たりし、理論式と一致することを確認する。
- **実規模 geometry:** 数学的な soundness 証明と安全な上界を導く。Monte Carlo の成功率だけで 128-bit を主張しない。

検出確率は、全 constraint の被覆、抽出率、代数検査の残余誤差、適応的な試行、source bias を合成して求める。

### C. 外部 1 人による客観裁定(G14。codex が担当)

**設定:** producer と Panel 全員を悪意とする。claim の公開後に起動した、fresh な通常の public bonded verifier を 1 人用意する。

**渡さないもの:** producer の heap、秘密鍵、非公開の debug API、攻撃注入用の instance、Panel の private cache。

**使うもの:** 公開 RPC と認証済み DA だけ。

**手順:**
1. 取得
2. 検査
3. 不一致の発見
4. 有界な局所化
5. 開示要求
6. evidence の提出
7. exact court または DA default
8. claim の無効化
9. 実際の担保処罰

**real node で含めるもの:** reorg、restart、IBD、Final 境界、複数 court の先取りと同時実行。

**判定:**
- 単独の public verifier が有効な proof を出したのに、共謀 Panel の署名や court 枠の占有によって排除されるなら FAIL。
- 故障を検出できなかったサンプルは、裁定の成功件数に数えない。

### D. 本当の処罰確率(MEAS・OPVB)

次の量を、それぞれ別に測定・導出する。
- `P_run`:期限内に、能力のある正直な検証者が実際に検査する割合
- `p_check`:その検証者が対象の不正を発見する条件付き確率
- `p_evidence`:発見した不正を、公開材料だけで局所化・証明できる割合
- `p_inclusion`:証拠が所定の期限内に canonical chain へ受理される割合
- `p_collect`:客観裁定の後、定義された担保を実際に徴収できる割合

`p_min` は独立性を仮定せず、条件付き確率と保守的な境界から導く。
- **実測で記録するもの:** 使用 hardware、claim rate、cold model の取得時間、p95/p99、最大 claim 数、DA の混雑、証拠 bytes、carrier 待ち、DAA と実時間の差。
- **監視者がいない場合:** 監視者がいない、または期限内に検査できない条件では、`p_min` を楽観的に補完しない。独立した FAIL/UNKNOWN として表示する。
- **閉鎖 model:** ADR-0177 の下では、閉鎖 model の `p` は 0 になり得る。これは独立した未解決の gate である。

### E. 経済攻撃と正直な監視者の収支(ECON)

次の攻撃を再現する。
- producer 自身の Sybil が、不正を発見したふりをして bounty を得る
- 先に proof を封印する
- 監視者の報奨金を希釈する
- seal を繰り返し置き換える
- 担保を一度だけ預けて何度も試行する

**正直な検証者の収支:** 不正がゼロの期間も含めて計算する(M\*-49 はユーザーが採用済み)。監視費用を賄う検査料は、計算量・公開証拠・検査完了条件に対して Sybil farming に耐えること。

経済モデルで成立しない阻止策を、コードが動くという理由で PASS にしない。

### F. 有効化判定(Lead が profile ごとに集約)

各 profile について、次の成果物を提出する。
- 全 relation の coverage 表と soundness の根拠
- 攻撃者にとって最適な不正配置と、実効的な検出・処罰確率の下限
- `G` / `L` / `C` の算出表、`EV` の最悪値、担保・検査回数・同時 exposure の必要値
- fresh な public verifier 1 人による、real node での客観裁定の記録
- 正直な検証者が継続して稼働できる費用・報酬の実測値
- 失敗した試験、仮定、残余リスク、未解決事項

結論は **PASS / FAIL / UNKNOWN** の 3 種類だけを使う。

**ActiveRewardable にしない条件(一つでも当てはまれば):**
- 検証できない報酬対象の計算関係がある
- 攻撃の期待利益が正になる
- 回収されない責任が残る
- 確率に不明な値がある
- 公開裁定の経路が欠けている

登録候補として保持することは認める。ただし PALW の報酬と consensus work weight は与えない。

## 5. 一つでも出れば有効化しない三つの反例

- **反例 A — 1 か所だけ改ざんすると、ほとんど検出されない。** 不正の配置場所を変えるだけで検出率が大きく下がる場合。代数的な全関係検査などで補強できなければ、必要な担保が非現実的な額になる。
- **反例 B — 処罰の前に担保を逃がす、または利益を持ち出せる。** 担保の重複予約、退出、reorg、外部決済によって回収できなくなるなら、経済式は成り立たない。
- **反例 C — 正直な検証者が経済的に参加できない。** 検証費用が高く、報酬を悪意の Sybil に奪われるなら、実際の監視はゼロに近づく。

## 6. 経済的抑止とは独立の被害有界化(safety 上限)

- 未決済の work weight の上限(ADR-0176 の `F_max` と、Final 前の暫定 weight の上限)
- 最大外部損失の上限(EVM・ブリッジ・市場への持ち出し)
- Final 前の払い出しの禁止(no payout before Final)
- 共通の拘束期間 `d + W` と、残存責任の担保との分離(ADR-0176 D4)

これらは BUDGET の engine と各 reward path に実装し、§4 の判定とは別に検証する。
