### RFC07: 実 producer → provider → native 受入

- [ ] own Consensus API が、実際の checkpoint・root・clock・登録 key に基づく opaque producer candidate を返す経路を完成させる。
- [ ] candidate → SDK の実 material 生成 → own ingress → 認証済み provider exchange → native covenant の受入確認 → 署名済み claim carrier の経路を繋ぐ。
- [ ] root が追加した private helper の `--private-probe-kernel-paid-work=ABSOLUTE_JSON` と runtime 実装を揃える。通常の shipped Args からは起動しない。
- [ ] producer 専用の payer・funding・fee/input/material/workspace 上限を明示し、owned outbox を broadcast 前に永続化する。再起動時は同じ署名 object・transaction を確認して再送する。
- [ ] 直近レビュー指摘を反映する: preflight の frame 長には実 byte 長を渡す。raw buffer と JSON/typed decoder の予約 owner を消費終了まで保持する。
- [ ] **過剰な Finalized 待ちの除去と受入経路の整合を完了する。** fold が要求する own accepted prior covenant と整合させる。初回 useful work が Finality を待ち、その Finality が useful work を待つ循環を作らない。GC/terminal の Finality 条件は別に維持する。
- [ ] broadcast ごとに tip/import/reorg と現在の covenant を再確認する。SDK draft・upload 成功・queued carrier を native 受入と扱わない。

新しい `--private-probe-kernel-paid-check=ABSOLUTE_JSON` は paid-v4 node 専用で、checker 自身の native bond/key、provider endpoint、取得上限、独立した receipt fee payer/funding を明示する。checker-only node は producer key や producer exchange を要求しない。Spec の read → own context で prepare → 専用 worker の start を接続する。通常の kaspad Args や公開 preset からは起動しない。

SDK reader は Program/Pipeline/Typed/Segmented の callback 取得と認証を接続し、全 immutable parameter の commitment と segmented parts の実再構成を照合する。返却 Tensor/bytes の owner と取得回数・総 byte 上限を保持する。旧 V3/V4 の canonical message opening は旧 root の認証用として保持し、provider の完全 scope root へ黙って置き換えない。取得失敗は Clean/receipt を生成しない。

実 checker は own native API の assignment/source を再取得して assigned seat の receipt を作り、送信前に object/transaction を永続化し、cold retry は同じ transaction を使う。これらは source 接続済みという保存境界であり、統合 compile・実 node 受入は未実行。negative finding の自動 court carrier、既存 canonical opening の冗長転送、全 checker/court の物理資源、source bootstrap の approved adapter は残る。
