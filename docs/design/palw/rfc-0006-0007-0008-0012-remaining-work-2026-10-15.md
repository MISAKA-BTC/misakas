- branch は `integ/rfc06-12-remaining`。基点は `origin/integ/rfc02-rfc06-12-g14`、push 先は `origin/integ/rfc06-12-remaining`。rebase と force-push はしない。統合 branch は明示 refspec で fetch し、定期的に merge する(直近は `08af47bab` の時点)。

  - `codex-wip/rfc-completion-integration-2030`(`89a317254`)
  - `codex-wip/rfc-completion-integration-final`(`1d622f430`)
- 補助 lane は 3 本で、すべて同じ規則で作業し、成果はこの branch へ merge 済み。
  - `integ/rfc06-12-gdn-router`(`973a76b98`、第 2 ラウンド `ee5202938`): GDN court・hybrid・router と RFC07 項目 1。

- **コード実装を先に揃え、その後で一括検証する。** この更新でも cargo の build/check/test/clippy、node 起動、測定は実行していない。
  - 下の「implemented」はすべて **source のみ・未検証(unverified)** で、受入成功や PASS を意味しない。
  - 実行したのは Python だけ: 生成器の冪等性確認(`scripts/drills/check_rfc06_native_wire_idempotent.py`)と、RFC12 harness の unit test(47 件)。
- RFC-0016・0017・ADR の実装は別 lane が担当する。
  - C1〜C5・U-3・U-4 等の値は測定とユーザー判断で決める。未承認値は本番設定へ入れない。
  - 新しい consensus 挙動は fence の内側で休眠させる(A-2 一様)。testnet-12 の挙動と preset は変えない。

恒久方針は [AGENTS.md](../../../AGENTS.md) と [PRINCIPLES §8](../../PRINCIPLES.md#8-モデル計算の暗号学的証明を使用しない2026-10-15ユーザー恒久決定) に従う。

- モデル計算の暗号学的証明は使わず、将来課題にも置かない。
- 確率的検出・決定論的再計算・公開局所化・裁定・経済的抑止を用いる。抽選された検証者の承認には、正直な割合等の前提を明記する。
- **optimistic Final や一致する local replay は、その承認を代替しない。**
- 合意 credit は RFC-0018 の SecurityCertified/Gate C だけを通る。
- DNS-BFT は `palw_dns_retirement_v1` で廃止済みで、安全性の根拠にしない。

## 0.5 DAA 14,000 有効化から見た状態

各 fence は測定値 gate を通らない限り武装できない(上表)。下表の「blocker」は `PALW_RFC0608_OPEN_BLOCKERS_V1` に載せた項目である(2026-10-16 時点)。これが残る限り、測定記録を pin しても武装できない。**どの fence も現時点では DAA 14,000 の有効化対象にできない**ため、休眠のまま載せる。リリース計画の原則に従い、ユーザー判断を仰ぐ。

| fence | blocker(コード/設計) | 武装に必要な測定記録 |
| --- | --- | --- |
| `palw_monetary_material_v1`(RFC08) | なし | event 基準の時間費用、recovery の liveness、provider 費用(RFC12 lane の `misaka-rfc08-cost-measure.py`) |

| `palw_paid_claim_trap_v1`(RFC07-5) | なし | trap 率、没収 ‰、signer liability、reveal window、commit deposit、setter の収支 |

### RFC-0006

- [x] 残る payout/exposure/court/aux writer、index、note/counter journal、caller 側の事前 clone・walk Vec・fold 一時領域を、予約 owner と実 consumer に接続する。 — **implemented (writers lane `b496ee2ba`, `f6f313c91`), unverified.**

- **問題:** 抽選された checker が検査せずに Clean receipt を出しても、producer が正直なら報酬を得る。不正が稀なほど、怠ける方が得になる。
- **選択肢:**
  - (a) **植え込み fault(trap)**: 既存の RFC-0007 audit mesh の `TrapCommittedV1`/`TrapRevealedV1`(tag 102/103、`H(claim ‖ fault leaf ‖ tiles ‖ salt)` の事前 commit と後の reveal)を paid claim に広げる。trap claim に Clean receipt を出した checker の bond と receipt 報酬を没収する。
  - (b) **承認者責任**: 後に conviction された claim の receipt 署名者は、receipt 報酬と担保の一部を失う。
  - (c) **検査 transcript の commit-reveal**: 公開 trace から写せるため、単独では効かない。
- **推奨: (a)+(b)。**
  - (b) は実装が小さいが、不正が稀なら抑止にならない。(a) の検出確率 p で下限を作る。
  - 条件は p × 没収額 > 検査費用(RFC08-6 の計測値)。trap 率と没収額は測定記録として pin する。
  - trap 自体は既存 fence `palw_audit_mesh_v1` の部品なので、新しい暗号要素は要らない。

### 4.2 長い source 閉路(RFC07-3) — **ユーザー承認、implemented (`195847e29`)**

- **問題:** `BeaconContextV1` は subject の claim/producer を持たない。現在の guard は自己 seed と 2 者の相互 source しか拒否できず、3 者以上の閉路を使った grinding は判定できない。
- **選択肢:**
  - (a) subject を持つ `BeaconContextV2` を新設し、fold で source 依存グラフの閉路を探索する(深さ・件数に上限)。
  - (b) **時間順序規則**: source の seal DAA が、target の commitment position より厳密に前であることを要求する。各 source は commit の後に seal するので、閉路を作るには A.commit < A.seal < B.commit < B.seal < A.commit が必要になり、矛盾する。どの長さの閉路も成立しない。
- **推奨: (b)。**
  - O(1) の比較で済み、新しい context version もグラフ探索も要らない。既存の `commitment_position` と source の seal 記録だけを使う。
  - 実装は休眠 fence の内側の 1 条件と反例 test。blocker 2 件を同時に閉じられる。

### 4.3 RFC06-6 Kimi の router — **ユーザー承認: この release では対象外(credit なし)のまま**

- **問題:** 宣言どおりの Kimi は、routed reader の幅が k·hidden で、ffn_dim の k block ではない。現行の per-reader binding では束縛できず、Kimi の routed gather は裁定できない。
- **選択肢:**
  - (a) Kimi 用の binding version と court terminal を作る。reader 形状 k×hidden、bound router の top-k による expert gather の再計算。
  - (b) 当面は裁定不能のまま coverage で拒否し、Gate C による credit 経路を与えない(unsupported 扱い)。
- **推奨: DAA 14,000 では (b)、実 model card の reader 配置を確認してから (a)。** genesis model(Qwen3.5/3.8 の GDN hybrid)は Kimi ではないので、有効化経路には載らない。

### 4.4 RFC12-7 DNS 退役の照合 — **ユーザー承認、implemented (`ecf7d1104`)。最終証拠は DAA 14,000 drill**

- **問題:** private profile は退役を DAA 1 で武装するため、fence 前の DNS 履歴が無い。coinbase ごとの DNS validator 取り分を読む手段も無く、旧 entitlement・報酬停止・reserve/exit の照合が BLOCKED。
- **選択肢:**
  - (a) coinbase の内訳(validator 取り分の出力と受取人)を返す読み出し専用 RPC。
  - (b) 退役を後の DAA(例 200)で武装する private-only profile。出荷 preset は変えない。
  - (c) harness 側で `getBlock` の coinbase 出力を `getDnsConfirmation` の bond の payout script で分類する。node の変更は不要。
- **推奨: (b)+(c)。**
  - node を変えずに、local の複数 process で fence 前後を照合できる。出力を script で分類できない場合に限り (a) を追加する。
  - 最終証拠は、DAA 14,000 をまたぐ出荷 binary の drill(実際の fence 前履歴を持つ)での同じ照合とする。

### 4.5 RFC06-8 の残り: fence 前に登録された legacy class — **ユーザー承認: この release では拒否のまま**

- **問題:** aux 141 は fence 以降の登録にしか書かれない。fence 前の class の admission bytes は state に無く、古い block 本体は pruning で失われ得る。このため、fold や snapshot 受入で全 node が決定的に再検証することはできない。
- **選択肢:**
  - (a) **レビュー済み pin 表**: 出荷 binary に、t12 の legacy class ごとの `(class_id, registered_daa, admission digest)` を pin する。archive node の census(RFC12 harness 項目 9 と同型)で実データから導出し、独立レビューを経たものに限る。fence の起動 block で aux 141 に書き込む。
  - (b) **祖先証明**: header の `parents_by_level` を使う対数長の祖先証明、登録 block の header、tx の包含 path を運ぶ migration object。
  - (c) 現状維持。complete snapshot capability では拒否し、該当 class は semantics 宣言(tag 164)か再登録で移行する。
- **推奨: DAA 14,000 では (c)、その後 (a)。** (a) は信頼の起点が明示されたレビュー済み記録で、measured-value record と同じ扱いになる。(b) は正しいが、設計と証明サイズの検討が大きい。

### 4.6 RFC08-2: 認証済みの出所が無い liability 項 — **ユーザー承認: この release では拒否のまま**

- **問題:** 結合 predicate の 7 項のうち、次の leg には署名済み・state 上の値の出所が無い。fence 以降は名指しで拒否している。
  - verifier check fee: verifier の liability horizon が無い。RFC07-5 と連動。
  - material provider fee: covenant の horizon が event 基準で、有限の点が無い。
  - native mining receipt と native admission: 署名済みの hard deadline が無い。
  - paid V2 enrollment 外の kernel claim: producer 署名の lifetime が無い。
  - source-fee payout。
  - trap window 前の audit answer。
- **既存の署名済み field で埋められる可能性があるもの**(writers lane の調査、未実装):
  - beacon source fee: sponsor 署名の `BeaconSourceFeeTermsV1` の `hold_until`・`final_by`・`deposit` は、horizon・hard deadline・K に使える。material TTL と retire に相当するものは無い。
  - material provider fee: covenant の `window_daa`・`enrollment_until_daa` は署名済みだが、役務の horizon は event 基準のまま。
  - verifier check fee: `Draw` row の `deadline_daa` は kernel が決める期限で、誰も署名していない。horizon には使えない。
- **推奨:**
  - DAA 14,000 では現状(拒否)のまま。`palw_settlement_once_v1` 自体が休眠なので、出荷挙動は変わらない。
  - 次の段階で、beacon source fee は `BeaconSourceFeeTermsV1` から horizon・deadline・K を取り、TTL と retire は「該当なし」を明示する項(値ではなく項の免除を版で宣言)として扱う。
  - material provider fee は、event 基準 horizon に署名済みの上限(`enrollment_until_daa` + window)を課す新 version で有限化する。
  - verifier check fee は §4.1(T6)の承認者責任の horizon と一緒に決める。
