# RFC08 bounded release recovery V2 — source checkpoint, 2026-10-15

Status: implementation source only. No build, test, node run, benchmark or acceptance measurement has been executed for this checkpoint. All public presets keep this fence `None`; its validator refuses activation while cost and provider-ACK liveness approval are unavailable. This document does not approve economic terms or declare RFC08 complete.

## Failure addressed

A V1 provider which missed the entire accepted Release interval could not recover its deletion authority after the old native delta/header was pruned. An absent covenant correctly retained material at MAX, but that was not a complete recovery protocol. Keeping an unbounded release index or treating absence as a receipt would not solve it safely.

A second issue arises after the last provider ACK: the terminal receipt disappears. A provider offline across its ACK acceptance and historical pruning cannot retire its outbox from old carrier inclusion. Moreover inclusion by itself does not prove that the lifecycle object applied: `palw_accept.rs` validates and rehearses each object and may drop it while retaining the carrying block.

## Explicit new contract and bounded state

`Params.palw_material_release_recovery_v2` and its Borsh-skipped state mirror independently own `PalwMonetaryMaterialActionV1::RecoveryV2` (appended discriminant 7 beneath existing outer tag 242). Old V1 variant bytes, Release discriminant 6, PAV3 header/Ready meanings and private paid-v3 factory bytes are unchanged. A2 classification, native signature checking, transition checks, Params identity/scale/reflection, and restore consistency include the new fence.

Recovery enrollment requires a fresh, unused, sequence-zero monetary covenant, sponsor and all provider signatures over a distinct recovery domain. It cannot backfill unavailable historical generations for an old used covenant. New work after this gate requires explicit enrollment before the first consumer. Replacement preserves existing paid/earned rights and requires both ordinary V1 replacement signatures and the additional recovery signatures of all new providers.

Aux137 (renumbered from 134 on 2026-10-15; 134/135 are RFC-0016's) has two exact key grammars:

* Root64: `PalwMaterialRecoveryRowV2::Active/Terminal`, including bounded signed generation/provider history.
* `0xA1 || Borsh(PalwBondKeyV2)` (69 bytes): `PalwMaterialProviderAckCheckpointV2`, one current ACK stream checkpoint per consenting provider identity.

Policy names finite reserved-contract, generations, history-cell and provider-stream capacities. Enrollment reserves the whole history envelope, terminal slot, provider stream slots and ACK sequence credits before recovery admission. Replacement reserves new distinct-provider slots/credits before its funding writes. Capacity refusal preserves the prior state and earned cash. Release needs no new table slot: after unchanged native actual-tail/finality and no-live-right checks, it replaces the existing Active row with a compact Terminal receipt. All distinct providers from every accepted generation must ACK before this receipt is removed.

Each ACK binds exact stream, previous receipt, receipt id and checked next sequence. The fold updates the provider checkpoint only when that ACK actually applies and consumes a previously reserved credit. Current native-finalized presence of the exact checkpoint therefore proves application after the last terminal receipt and historical carrier/delta have disappeared. Stream retirement is separately provider-signed and refuses every accepted active or unacknowledged terminal obligation and nonzero reserved credit. Local outbox emptiness is not a consensus authority.

## Provider recovery and ACK consumer

The local Consensus API reconstructs the parent-state committed by a current native-finalized header, checks its committed root and strong consistency, and refuses incomplete/moving pruning imports or changed virtual tips. A terminal receipt present in this state authorizes only its exact root and recorded stored generation. It does not need the old Release header/delta. Missing/reconstruction-unknown facts retain material.

Op242 already authenticates the complete aux table. The proof pager now retains and structurally preflights aux137 rows as well as aux120; `finish_with_recovery_v2` alone constructs `ProvenMonetarySnapshotV2`. The V2 remote GC oracle requires this complete proof plus the separately configured native finality authority. Intermediate pages and RPC availability booleans are not release authority.

The provider GC janitor tries the current finalized terminal receipt even if it never observed the active covenant. Its deletion intent and exact native authority-index cleanup receipts remain fsynced/replayable across crashes. The provider signs an ACK only after every generation it served has a verified durable deletion receipt and authority metadata cleanup is fsynced. Its outbox uses an exclusive kernel lease, bounded structural preflight and atomic publication. Exactly one ACK per provider may be signed/in flight. The next ACK cannot be signed until exact current-finalized stream/sequence/receipt presence retires the preceding outbox entry durably. This prevents a later local ACK from overwriting the one checkpoint needed after a long offline interval.

`into_hook_with_service_v4` exposes the hosted service to an explicitly configured private fee-payer adapter. The parent integration owns the private v4 funding UTXO/key/fee cap, actual carrier signing, mempool submission/retry and checkpoint retirement worker. Submission itself is never retirement authority. The V4 runtime path now creates and signs a fresh prospective session through the provider exchange before native consumer admission. A fixture bootstrap is not used as a substitute for this runtime path.

## Native allocation ownership

Provider snapshots now use a retained native owner for their full lifetime. Reopen preflights the outer provider store, all embedded material bundles and embedded kernel position/segmented response codecs before Borsh. The owner-specific mutation path derives logical requests from actual typed heap/memberships, canonical encoded byte counts, concrete BTree allocation envelopes and coexisting decode/response/publication copies. Raw signed material capacity is a separate storage limit and is not relabeled as native RAM or physical RSS approval. Strict bare-value extraction is refused; owned answer/publication methods retain their tickets. Physical allocator/RSS approval and all-model actual acceptance still require the later measurement phase.

### Actual kernel ingress / cold consumer source follow-up

The private provider transport appends purpose `KernelMaterialIngressV4` (2). Native Ready purpose 0 and native prospective enrollment purpose 1 retain their old wire meaning. A producer signs the exact actual SaltedCommit, prior roots, finite admission deadline, canonical native provider roster and complete material manifest. The provider's own node replays that work against its own accepted checkpoint and obtains actual registered keys and collateral. Its canonical draft atomically combines ordinary monetary service and RecoveryV2 enrollment; the configured sponsor pays its own fees. A transport success or queued transaction is not native admission. The actual producer must wait for the matching native consent/recovery generation before sending its claim.

`TypedKernelV4` (codec 3) is distinct from legacy position/segmented codecs. Its complete inventory includes original native positions, memory entry state, all retrieval snapshot slices/entries, canonical segmented parts (stage 254) and immutable artifact rows/tiles (stage 255) using the actual registered root suite. Legacy v2 row roots are never silently retiled under v3 roots. Actual unsupported unit/carrier shapes refuse before funding and remain an open coverage limit, rather than evidence that every model is supported. Merkle membership and signatures authenticate data identity; they do not prove model computation correctness. This follows PRINCIPLES §8.

Before its liability response, each configured provider durably publishes a separately bounded `kernel-context-v4` sidecar, its full material snapshot, and its original provider signature capsule. The first metadata format retains the actual prior route instead of manufacturing a selected class row. It is bounded by explicitly configured local native RAM/DB limits divided among the endpoint's hosted provider identities; no capacity is invented when those inputs are absent. Metadata is separate from signed raw material capacity. A dedicated archive RAM budget sums its persistent map, raw/open decode overlap, every outstanding returned row owner, borrowed insert inputs for the duration of the operation, identity buffers, candidate clones and encoded publication buffers before allocating. Returned metadata rows retain both the archive-local lease and process-native lease until their last borrow ends. It limits rows, compares canonical snapshots, and reserves both DB publication generations plus a fixed expiry intent. Native own-state grants and candidate replay have separate process-native ownership; the archive cap does not cover callers retaining unrelated native grants outside archive operations. The process native checker aggregates those process owners. These are logical local bounds, not physical RSS or economic approval.

Cold recovery authenticates raw bundle content against its saved manifest while granting only retention. A current accepted monetary/recovery generation, exact scope, actual provider key and original provider signatures are required before reconstructing the intrinsic candidate for an answer. The context's prior ledger/aux roots and producer signature are rechecked and the actual SaltedCommit is replayed. No historical Release header, indefinitely retained old ancestry, missing row, or local completion Boolean becomes authority. All retained generations are considered after the preferred consent, and an ineligible first generation cannot hide a later eligible one.

Normal native finalized GC deletes this metadata before the durable completion permits an ACK; its existing write-ahead intent replays this step if raw material was already removed. Never-admitted residues use a separate fixed-size expiry intent, the original signed enrollment deadline and the own-node native finalized impossibility check. Active or terminal recovery rows refuse this shortcut so released generations still produce the normal GC completion and ACK. Any unavailable read retains both material and metadata. Earned cash and consensus clocks/windows are unchanged.

Remaining acceptance work includes actual all-target producer/provider handoff, positive native fees and reward payments, court answers after cold reopen and admitted reorg, raw+metadata deletion/ACK across injected crashes, the explicit local metadata cap under large actual routes, and independent-host availability. ### Authenticated checker unit transport (source only)

It does not silently substitute another retained consent. Unit bytes are at most 64 MiB, and response framing/workspace is additionally bounded by the accepted scope's actual total bytes. Raw frame, outer response, decoded unit and output buffers have separate retained allocation reservations. The byte owner transfers to the caller without a deep copy or a dropped ticket. ### Immutable funded ACK and additional-carrier retry (2026-10-24)

The provider ACK outbox and additional native-carrier queue now refuse to replace a previously saved transaction with a different spend, even when its lifecycle payload is identical. An identical retry compares the complete canonical transaction against the existing bytes through a borrowed streaming writer, performs no publication, and preserves the ACK's accepted-block hint. This path does not allocate a second transaction encoding, decode the saved transaction, or clone the queue before deciding whether the retry is allowed. The caller's transaction and the existing WAL bytes remain borrowed inputs.

Cold reopen preserves this same restriction. A reorg may re-include the saved spend at a different block through the existing accepted-block update; that hint still cannot retire an ACK without positive native finality/application. The existing explicit release-only proposal replacement remains available for a changed reorg tail and deliberately resets that proposal's submission. The general submission retry API cannot perform that reset or silently create another funded spend. No previously overwritten historical transaction is reconstructed or inferred.

The regression sources exercise actual atomic WAL publication/reopen, identical retry, changed funding with an identical signed payload, retained inclusion hints, false-finality retention, and the explicit release-proposal reset. Their signatures and finality callbacks are storage seams; these cases do not establish actual native acceptance, payment profitability, provider independence, full material recovery or the all-target campaign. Public activation and unapproved private source economics are unchanged.

### Preserve op242 provenance through remote GC (2026-10-24)

`ProvenMonetarySnapshotV2` previously discarded the pinned header and parent identities after completing its authenticated aux proof. Consequently `RemoteProofGcOracleV2` could accept a callback's valid snapshot of a different header as the requested current finalized state. The completed snapshot now retains both hashes; every subsequent page must keep the same parent header. The remote V2 GC consumer requires the snapshot's pin to equal the native-finality authority's requested pin and its parent to equal that authority's selected parent. Membership in the header's DAG parent list alone does not satisfy the latter condition. It rechecks finality after reading the proof. A foreign snapshot, changed parent, changed finality or failed read is unknown authority and retains material and any interrupted deletion intent.

This changes the existing remote V2 consumer, not the private node's direct `ConsensusGcOracleV3`. The new fields are local opaque proof metadata; no consensus/object/RPC wire, activation, monetary policy or model rule changes. Header/aux hashes authenticate data identity and location, not model computation correctness. Current receipt presence still permits recovery after historical release headers are pruned; the saved intent's old header is not made an additional pruning prerequisite.

Three tests use the actual op242 pager, header hashes, state preimage and aux commitment: completed-proof provenance, a different valid pinned proof or non-selected DAG parent, and finality movement during the read. A fourth regression uses the actual typed provider store and GC janitor: after a foreign-proof refusal it fsyncs an interrupted-deletion marker, reopens both store and journal, and confirms that revalidation retains identical material bytes and the intent without producing a cleanup/ACK receipt. Finality is explicitly injected in these fixtures; the headers are not mined, and these runs do not demonstrate real native finality or a multi-node restart/reorg/pruned-IBD campaign.
