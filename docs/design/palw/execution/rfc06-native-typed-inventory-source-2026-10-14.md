# RFC06 typed native inventory — source checkpoint (2026-10-14)

This checkpoint has **not** been compiled, tested, benchmarked or exercised on a node. The user ordered all remaining code before consolidated validation. Existing native 100k and old codec timeout evidence predates this change and is not validation of it.

The accepted pruning capture now stages a compact point/root-bound inventory in the same RocksDB batch as the canonical snapshot. No optimistic metadata cache is published before commit. A fresh store reads compact metadata rather than decoding a giant native state merely to reject a local capacity request. The metadata has a bounded local encoding and integrity checksum; neither that checksum nor peer-provided metadata is a remote resource proof.

The generated visitors exhaustively destructure native fields and enum variants. They cover primary carriage rows, private restoration due/reverse indexes, nested vector capacity, retained Arc payloads (aliases counted conservatively), Panel engine COW candidates, both lifetime authorization families, and the retained kernel ledger with its private derived indexes. Source additions require regeneration. BTree allocation-request envelopes are pinned to the repository Rust 1.93 / 64-bit layout; other target layouts refuse nonempty trees. Logical requested bytes are distinct from allocator RSS.

The optional `--palw-native-logical-admission-v1` reserves aggregate typed demand with an RAII lease through snapshot transfer. Simultaneous source/carriage/restore/cache copies, known encoded Vec lifetimes, fixed chunk/deflate buffers and root scratch are separate terms. An actual accepted state provides installation inventory via `reserve_native_install_v1`; serving metadata cannot authorize installation. Unsupported and arithmetic overflow remain structured diagnostics. Defaults preserve historical behavior.

Physical memory approval requires observed Linux cgroup-v2 membership, finite `memory.max`, current usage, a verified kernel mount, confined path and a membership recheck. This does not install a quota or treat configured bytes as enforcement. Other targets lack a implemented hard-memory-quota evidence provider. Quota evidence is refreshed, rather than accepted from a peer or persisted metadata. External changes to quotas/membership are not a perpetual quota guarantee.

Installation still explicitly refuses whole-DB physical coverage: per-block retained delta/history, archival rows, concurrent WAL/log retention and compaction/live SST copies lack an enforced finite DB quota provider. Point-only encoded payload sizes and measured fixture disk/RSS are not substituted for these unknowns.

Remaining code: audited predecode structural Borsh walker and restoration-index shape bounds for untrusted receive; enforced filesystem DB quota backend/evidence on supported targets; RPC publication if required beyond the public Core consensus diagnostic API. Strict native capabilities refuse receive while its wire shape is unknown, even if a local inventory names the same point. This checkpoint does not close whole native physical RAM/DB or pruned P2P acceptance.

Consolidated validation must check all schema visitors against actual accepted rows, cache alias accounting, Vec capacity, overflow, concurrent lease saturation/release, snapshot batch failure/abandon, fresh-store metadata publication, point/root integrity, quota negative cases and all manual Borsh codecs. Tests are included as source only.


## Structural wire and enforced DB quota source extension

Source now includes generated Borsh structural visitors for 533 concrete native/admission/aux types, actual nonzero enum discriminants, the manual legacy carriage and 72 tagged tails, version-conditioned BondBudget codecs, model-market flags, and Panel candidate COW Vec allocation. The real stream is walked before native allocation; malformed/truncated counts cannot substitute for a resource estimate. Byte Vecs and fixed digest arrays are skipped in bounded buffers rather than one byte per scanner allocation. Private restoration index envelopes use reviewed source-table counts and nested ownership counts. Later native aux decodes at tables 32–41 and 107–124 use their exact canonical types; aux119 has the new explicit economic/independence envelope. Unknown nested aux schemas refuse the strict capability. Unparsed kernel ledger class/program expansion remains a separate later consumer operation, rather than being approved by opaque row byte lengths.

The protocol-107 receive lease is retained in its IBD owner through decode, state/root validation, atomic install and synchronized WAL. Error/cancel/attempt completion releases it. Legacy/106 receives retain historical behavior when local native flags are off; explicit native admission requires the negotiated 107 structural preflight. Quota evidence and resource shape do not authorize a root or execution declaration: existing cryptographic/semantic checks remain mandatory.

Install can now obtain whole physical DB coverage only through an actually observed enforced XFS project quota on a proven single-directory RocksDB factory path. Discovery verifies nonzero inherited project id, normal-data allocation, quota accounting AND enforcement, finite hard limit, and existing regular DB files sharing project/device. Arbitrary DB::new, external WAL, mutable replacement, symlink/nested layouts, unsupported filesystem/ABI/platform and missing quota evidence refuse. The kernel hard limit covers retained history, WAL and concurrent compaction files collectively; project pressure can still fail the batch. No host quota or project is created/changed, no configured number becomes enforcement, and no quota syscall or OS acceptance test was executed.

The ABI implementation was derived from primary [Linux quota UAPI](https://raw.githubusercontent.com/torvalds/linux/v6.12/include/uapi/linux/dqblk_xfs.h) and [filesystem UAPI](https://raw.githubusercontent.com/torvalds/linux/master/include/uapi/linux/fs.h). All source in this extension is still uncompiled and untested. The new source tests must be run only during consolidated validation, including actual native 100k snapshots, every populated optional/manual codec, all negative preflight cases, nested aux schemas, real enforced quota behavior and disk-failure atomicity. No source generation count is a validation result or physical capacity approval.


Aux115/123 key65 indices use the actual `PalwPaidClaimIndexV3` schema (version/kind/owner/target), with prefix/length dispatch distinct from key64 primary rows. Restore's temporary per-job and per-producer fixed-key counter maps are explicit scratch terms. Standalone RPC/client rows can use `preflight_native_value_v1::<T>` before Borsh allocation; its privately constructed proof returns logical requested bytes and exact canonical size for aggregate client capacity admission. Persisted Vec/String inventories cover both observed capacity and pinned Borsh clone/restore growth, rather than assuming a captured Vec capacity bounds the deserialized cache.
