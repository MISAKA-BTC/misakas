# Per-attempt beacon source reservations — dormant implementation

This is the ledger part of ECON §4.7 S3/S4. It is **not** their node/security/economic closure. The existing sealed-source v3 collector still mixes ordinary job-race seals. No deployed parameter supplies the new source fence or target inventory. No approved source deposit, fee, concurrency or liability tuple is introduced.

## Accepted contract

Inner kernel tag **21**, `OptInBeaconSource`, signs `(producer, job, seal, context_id, terms_id)` through the existing signature-verified kernel route. It is 322 encoded bytes; its hard parser ceiling is 384. This does not alter tag 20 or a Round ticket. The native inner-kind table and admission gate assign tag 21 to **`Params::palw_beacon_source_opt_in_v1`**, separate from OPV. All presets hold `None`; any real height is refused by config validation. Its optional value is hashed Some-only in both fingerprints, and `never()` is removed by identity normalization. The ledger also requires an explicit, separate `activation_daa` from its consumer and the existing OPV fence. Default and row-restored admission inputs are empty, so tag 21 is refused.

The consumer supplies the **authenticated frozen target**; object bytes cannot create one. The context ID includes the complete `BeaconContextV1`, including subject, chain/ruleset/policy, epoch, accepted commitment position, candidate and both frozen profile sets. Source terms additionally bind all three window boundaries, a source Final deadline, its liability/material hold horizon, its separately reserved deposit and producer/global concurrent caps. Checked clock arithmetic refuses overflow. A zero deposit/cap, impossible horizon, or an unrepresentable release after `u64::MAX` is refused. The deposit values in tests are fixtures, not the derived 28.6 BILI policy.

A source needs its producer's own live salted-race seal, in the target's seal window, with enough ordinary seal TTL to survive its reveal window. The source profile must be frozen eligible OPV work, outside the candidate/dependency exclusion set; its job needs an authenticated retained payer. Only the node's currently exported ordinary/program and pipeline job forms are accepted. Segmented/typed jobs require their own complete authenticated source adapter.

Every target takes a **fresh source reservation**, in addition to the unchanged ordinary race deposit. Existing reservation receipts (`ReserveSealDeposit`, `ReleaseSealDeposit`, `ForfeitSealDeposit`) already have the required collateral/reservation effects; table 28 records which reservation is the source contract. A target/producer pair is used once forever. Failure, replacement or refund cannot replace its mixed seal. All in-horizon rows count toward concurrent caps, even after their deposits burn; changing caps cannot bypass a stricter still-live contract. For a single ordinary seal promised to several targets, the reveal windows must intersect, and its reveal is refused outside any of them.

## Money, clocks and recovery

Table **28**, keyed `(context, producer)`, retains the job/profile/payer, exact seal and accepted position, opt-in position, terms, held amount, revealed claim/position, and permanent forfeit/refund outcome. The optional source root extension is absent when this table is empty. Ledger roots and row-derived roots compose the extension in the same order, after EXEC holds. Row reconstruction validates bindings, revealed salted openings, source liability and held collateral; it clears the new consumer admission inputs. It does not clear existing contracts.

A successful salted claim admission returns **only the ordinary race deposit**. Source deposits remain reserved. Admission also extends that claim's material/collateral liability to every live signed source horizon. A claim Final retains both reservations through that horizon; Final is not a source-deposit refund. The tick refunds the source reservation once, only after the horizon and only for a standing source claim that finalized by its signed deadline. Returned principal is not source income.

Resealing or expiry burns every live source deposit attached to the replaced seal, independently of the ordinary seal deposit. A missed reveal, source conviction/default/timeout, or missing timely Final also burns the separate source reservation. Failed source metadata remains. In particular, several reseals at the same DAA cannot overwrite the per-target source row. This does **not** repair ordinary v3 table 26's older `(job, producer, sealed_daa)` collision: do not infer full v3 S1 closure from these new opt-in tests.

The row journal and scalar journal must both roll back with the consumer's block. The tests exercise exact row/scalar undo and rebuild against the old root, along with settlement-book conservation. This is kernel consumer evidence, not actual node restart/reorg or P2P evidence for the new feature.

## Remaining connections and acceptance

Before S3/S4 can be claimed implemented on the node, the native fold must derive these inputs from actual rooted target rows and the new dedicated closed parameter fence (`palw_beacon_source_opt_in_v1`). The native tag/fence gate exists; the native fold does not yet inject a target inventory into the ledger. It must freeze the **deposit minimum, concurrent caps, finite source-Final deadline and entire target liability/material/court horizon** before signatures. The foundation currently validates these trusted terms; it does not derive or approve their economic minima or worst-case inclusion budgets. Intersection of reveal windows alone does not prove inclusion in the intersection.

A new source-only beacon policy/version must enumerate exactly the opted-in, context-bound facts, keep every eligible failed contribution as a veto, and preserve the verified-row/SDK subject binding. **Do not filter the old v3 collector in place**, silently reuse its policy ID, or reinterpret historical contexts. Target adapters are required for onboarding, Panel assignment and claim verification; unsupported contexts must be explicitly refused. Ordinary race losers must have no new-policy veto.

Source fees still need signed, actually collectible funding from registrants, reservation, minimum net receipt and once-only Final-dependent vesting. Watcher/source capital costs and zero-volume solvency are still separate unresolved economics (§5f); no issuance or unfunded stipend is added here. S2 retry/lifetime soundness accounting, Sybil/source independence, censorship, composed soundness approval, and public class security approval remain open. The hard binary live-slot ceiling is a defensive implementation bound, not a demonstrated 100k-class resource/throughput gate. The book retains historical rows and currently scans them; indexes, bounded history/snapshot rules and measured scale remain required before activation.

Required node evidence includes signed admission/refusal, separate charges for N victims, cheap ordinary seals excluded by the new collector, withholding/reseal/abandonment/public conviction including after source Final, deadline and low-demand cases, once-only refund and actual node restart/replay/reorg, served-row SDK verification, pruned/P2P recovery and realistic concurrent load. The existing v3 many-victims regression is expected to remain negative until those consumers and the new policy are connected.
