# ユーザー判断 2026-10-15 — ADR C1〜C5・RFC-0016 V2〜V11・RFC-0017 U-1〜U-9

**Status:** ユーザー判断(設計方針の採用・修正指示)。**数値は校正・受入試験の出発点であり本番値ではない。新規 fence の有効化は承認していない。**
対象: 統合ブランチ `integ/rfc02-rfc06-12-g14`(`6b1a01acd`)の判断事項
([ADR 判断事項](adr-0162-0178-user-decisions-2026-10-15.md)、[RFC-0016 §14.1](../../rfc/0016-bond-weighted-block-opportunity-and-elastic-final-capacity.md)、[RFC-0017 §11–12](../../rfc/0017-model-eligibility-examination-and-renewal.md))。

## 基本方針

- DAG の並列生成を維持する。異なるモデルの miner が同時にブロックを生成でき、適格な RED の仕事も取り込む。
- α=1.5、30 日平均 bond、V+、既決定の拘束期間は変更しない(再審しない)。
- モデルの登録は自由とし、通常の採掘資格とは分離する。
- 検証されていない計算に、無条件の合意上の優位を与えない。Final weight を 0 にするだけでは safe frontier や決済深度まで 0 になるとは限らない。
- 測定前の暫定値は calibration/devnet 専用とし、本番 activation を禁止する。
- 最も重要な原則: **モデルの採掘資格と、計算がチェーンの安全性に寄与できる資格を分離する。**

## 1. ADR C1〜C5

| 判断 | 回答 | 指示 |
|---|---|---|
| C1: R_total の範囲 | 条件付き採用 | 新規発行される miner 向け coinbase 報酬は、経路を問わず実際の支払が R 上限を迂回しないようにする。利用者払いの取引・サービス手数料は既決定どおり別会計。拒否された claim への補助金支払が残るなら、coinbase 側を修正してから有効化 |
| C2: Panel=1 のみの bond の出金拘束 | 採用 | 出金拘束は 7 日相当を維持。Panel=1 の発行能力の回復は 1 日相当でよいが、出金・再登録・mode 切替で長期責任や枠を初期化してはならない |
| C3: Round 権利・income の rate | 修正して採用 | 7 日総量だけでなく短期間の集中発行を制限する rate/burst 上限を要求。同じ元本を複数の収入経路で二重に使わせない。具体的な rate は実測待ち |
| C4: P_m の二重適用 | 既決定を追認 | 物理ブロック機会は RFC-0016 V+ が 1 回、coinbase 配分は ADR-0177 が 1 回だけ適用。V+ 有効時は V3 の別の `block_opportunity` を無効にする |
| C4b: 利用者払い escrow | 修正して採用 | coinbase 由来のモデル予算に基づく claim 別上限 `r_c` を利用者払い escrow に転用しない。producer 共通 R 上限と必要担保は維持。不足するなら受理前に拒否し、受理後に減額しない |
| C5: Verifier 資本の定義 | 条件付き採用 | 実際の検証責任・拘束期間・処罰対象が定義された適格な資本だけを数える。Panel=0 で単に bond を登録しただけの資本は加算しない。OPV の検証責任会計が完成するまで当該新規資本の配分寄与は 0 |

C1 と C4b は既存の報酬会計や coinbase 処理の変更を要し得る。方針の採用と現行コードの合格は区別する。

## 2. RFC-0016 V2〜V11

| 判断 | 回答 |
|---|---|
| V2: σ・φ・pace・再配分 | 途中再発行は `A_m` 加重方式を採用。校正初期値 σ=0.25、φ=0.5、pace margin=1.2、仕様の全候補を測定。`k=1` で追加 ticket 傾斜は無効のまま。本番承認は保留。`A_m` 欠損時に先着 fallback で不当に権利を与えない |
| V3: entrant reserve | 校正案としてネットワーク総機会の 20‰ を上限。RFC-0017 の Probation 予算と 2 重確保しない。Probation のモデル別上限 2‰ を校正値として維持。`S_entry` は対象ネットワークの適格な最低 producer bond を基準にし、適格性のない資本を含めない |
| V4: Q/B/R/F・担保 | 測定で確定。最小 bond の正直な miner が継続採掘でき、高速偽造者がそれ以上の枠を得られず、責任担保も不足しない組合せだけを採用。必要なら claim 一件の権利を小さくする。元本や上限を無条件に引き上げない |
| V5: epoch 期間 | 初期校正は 720 DAA = 1 epoch。30 日平均の名目窓は 21,600 DAA。実時間と DAA 進行のずれは報告し、1 epoch が常に実時間 24 時間だとは表示しない。本番値は実測後 |
| V6: 合格閾値 | 安全性・会計の不変条件違反 0 件を必須。honest miner の cap 利用率 80% 以上を校正目標、V+ なし同条件に対する継続 REAL 生産の劣化は暫定 5% 以内を目標。新規モデルの最低機会保証と T4 の最終数値は E1〜E6 の実測で確定 |
| V7: queue・quote | 有界 queue と bond 資本比例の公平配分を採用。`L_queue`・`T_queue`・`h` は実測で決定。quote は確定権利ではなく、競合時は決定論的に再検査。TTL 超過は不正認定せず終了 |
| V8: 容量 attestation | モデル・verifier・能力・測定窓・期限・証拠 root へ署名して固定。各 verifier の容量はモデル間で二重計上しない。`sigma_cap` はまず 1 以下の校正候補、測定根拠のない容量増幅を禁止。計算量・メモリ・DA・court 負荷を一体評価 |
| V9: verifier 報酬 | 既存の 10〜30% を維持、校正基準 20%。負荷による傾斜と検査数 `N/m` は実測で決定。実際に検査した割合 `checked_share` と期限内の検証完了率を別々に計測。新規発行を増やして解決しない |
| V10: 未配分報酬 | attestation 未達で留保された補助金は他モデルや未検証 claim へ自動再配分しない。その epoch は未発行扱い、後日の追加発行で取り戻さない。発行上限を維持 |
| V11: coinbase の Panel 変更 | 今回は移行しない。V2 Attempt の既存 Panel 経路を維持し、Kernel/OPV の Panel=0 と区別。検証・rotation・責任・Final の実ノード試験後に別途判断 |

V2・V3・V5・V6・V8・V9 の数値は校正・受入試験の出発点で本番値ではない。V+ で権利を多く配っただけで、実際の計算・採用ブロック・Final・報酬が増えたとは判定しない。

## 3. RFC-0017 U-1〜U-9

- **U-1:** Registered → Probation → Eligible → Lapsed は採用。7 枠・4 承認は本番用として承認しない。ECON の 47 枠・24 承認を優先的な校正候補とし既存制度と整合させる。その他の設計値(Probation 7 日・16 claim、30 日更新、試行回数、2 日承認窓など)は試験用として維持、本番値は保留。
- **U-2:** Probation の Final weight=0 を採用。追加条件(activation 必須): Probation claim の Final を合意上の安全性 credit と混同しない;`safe_weight` と `bounded_immature` への寄与 0;`safe_frontier`、PALW の settled anchor 深度、Rule E の参加数を認証なしに進めない;Probation が発行できる物理 REAL block 自体の GHOSTDAG・DAA への影響は別途有界性を検証。現行の `F=0` だけではこれらを保証できない。
- **U-3:** stake 比だけで独立検証の成立を保証したことにしない。単一試行の自己承認通過確率(RFC-0017 §5.1 解析値): f=3% で 7/4 0.0026%・47/24 ほぼ 0%;f=33.3% で 17.3%・約 0.9%;f=60% で 71.0%・約 91.8%。全体 verifier stake の悪意ある支配割合 `f` を独立した脅威モデルとし、少なくとも f=1/3、f=0.6、最悪ケースを評価。実際の正直な verifier 比率をチェーン上で証明できない以上、抽選結果だけを無条件の計算正当性証明にしない。モデルの通常資格と、個別 claim をチェーンの安全性に使える証明は別に扱い、後者には検証可能な計算証拠と公開裁定条件が必要。
- **U-4:** 100,000 BILI は本番値として不承認(t12 の最低 producer bond 13,000 BILI より大きく、小規模な正直参加者の障壁になる一方、300M の攻撃者は止められない)。試行手数料の非返還・burn は採用するが金額は実測の検査費用から導出。lineage 単位の試行上限、ネットワーク上限、cooldown、公平な待ち行列を併用。正直な新規モデルが資本不足だけで参加不能にならないようにする。試行費用は (a) 取消し・失敗でも返還しない spam 防止の burn 手数料 と (b) 検証者へ支払うため事前に資金確保する検査費用(申請者負担の escrow 等、新規発行にしない)に分離する。全額 burn 実装を維持する場合も検証者の報酬原資を別途確定する。
- **U-5:** 1 更新期間(名目 30 日)の移行猶予を採用。既存 claim の権利・責任は維持。猶予を新規の未認証 security credit を無制限に発行する免除として扱わない。更新審査に通らなければ Lapsed。
- **U-6:** 永久の全面免除は不採用。非報酬の緊急 liveness を維持する BASE-0 には専用例外を認める。その他の報酬付き genesis モデルは既存モデルと同じ移行・更新審査を受ける。
- **U-7:** 当面は併存。RFC-0017 をモデルの資格・更新 gate、ECON を対象 epoch の検証と支払 gate として区別。同じ検査を二重計上・二重請求せず、必要な条件が未成立なら対象の支払を解放しない。置換は同等以上の検証が実証されてから。
- **U-8:** 採用。`roll_epoch` で決定論的な資格 snapshot を読み、Registered/Lapsed のモデルを配分の分子・分母・ブロック機会から除く。reorg・IBD・再起動で同じ値になることを必須試験とする。
- **U-9:** 採用。Registered/Lapsed のモデルは報酬や improvement score の昇格を生む評価経路で拒否。ただし登録・試験のための利用者払い Kernel/Funded job は維持。

## 4. 全 agent 共通の追加条件(新規 fence 有効化前に必須)

| 優先度 | 必須条件 | 理由 |
|---|---|---|
| P0 | Probation の Final weight=0 と、frontier・settled depth・参加数の不算入を一貫させる | weight だけ 0 でも合意上の優位が残り得る |
| P0 | Rule E の Voided attempt・bond 分割による参加数の問題を解決 | 資本額と独立した参加数の増幅を避ける |
| P0 | RFC-0017 の 47/24 を独立した計算証明と誤表示しない | stake 支配率が高ければ自己承認が可能 |
| P0 | R_total、coinbase、利用者 escrow の全経路を整合させる | 予算上限を経路の違いで迂回させない |
| P1 | 300M BILI の閉鎖モデル攻撃を 30 日・90 日の条件で評価 | モデル集中、分割、検証者支配、反復試行を比較 |
| P1 | 複数モデルによる DAG 並列生成、RED 取り込み、reorg、IBD の E2E 試験 | DAG を維持したまま合意が収束することを確認 |
| P1 | heartbeat・BASE-0 の継続稼働試験 | 資格・容量・検証待ちが時計を止めないことを確認 |

PRINCIPLES §0 が許容する `p=0` の残余リスクは、経済的な損失上限とチェーンの確定性を区別して扱う。モデル資格制度だけで frontier 優先 fork choice の問題が解決したとは宣言しない。

## 5. 統合・有効化

- **設計方針の採用:** 推奨(C4、V+、段階的モデル資格、Probation の Final weight 制限、GAP-E1/E4 の接続方針など)。
- **測定用コードの統合:** 生成物再現性・cargo check・対象テスト・影響スイート・clippy・未有効化時の旧ルール同一性が PASS したコードは休眠状態で統合してよい。
- **本番パラメータ確定・fence 有効化:** 承認保留。σ/k、Q/B/R/F、検証者資本の前提、手数料、queue 容量、モデル資格の安全性、実ノード試験が揃うまで有効化しない。
