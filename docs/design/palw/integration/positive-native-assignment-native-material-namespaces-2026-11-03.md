# RFC-0045 native material namespace inventory — 2026-11-03

This implementation inventory specifies native journal auxiliary DATA preimages within adopted RFC-0045/ADR-0213. It introduces no new body operation, no acceptance shortcut, and no computation certificate. All four purpose domains below are new native adapter material domains. Existing r1 Result, Witness, execution record, output, funding consent, Case journal event/history and Positive certification subject identities retain their exact meaning and bytes. Relay operation 14 under the separately adopted RFC-0046/ADR-0214 remains outside this inventory.

| Domain | Exact preimage | Actual origin |
| --- | --- | --- |
| `misaka/positive/assigned-case-native-boundary/v2/r1` | Fixed 496-byte canonical Borsh `AssignmentCaseBoundaryV2` below | This accepted native Case event |
| `misaka/positive/assigned-case-populated-inputs/v2/r1` | Canonical Borsh tuple `(2u16, 1u16, actual_transaction_id, actual_populated_input_entries)`; slice carries ordinary LE u32 count in transaction-input order | This accepted native Case event |
| `misaka/positive/assigned-record-header/v2/r1` | Exact canonical Borsh existing A0 `RecordHeader`, already versioned and Result-bound | Literal accepted op1 |
| `misaka/positive/assigned-generated-ids/v2/r1` | Literal generated token bytes, each little-endian u32, with **no additional Vec length prefix** | The same literal accepted op1 |

Each domain uses the repository's keyed BLAKE2b-512 identity recipe. The boundary fields, in order, are `version:u16=2`, `revision:u16=1`, `case:CaseId`, `origin:AcceptedOrigin`, `selected_parent:NativeHash64`, `pre_event_root:Digest`, `before_delta_end:u64`, `populated_inputs:Digest`, `input_count:u32`, and `fee:u64`.

The writer captures the real native pre-event state root and delta length **before any writes by the event**, including resource/P/funding writes. It derives the expected reference list itself, sorts and deduplicates canonical serialized AcceptedMaterial bytes, and emits exactly that list. The record's own auxiliary list cannot supply its expected references. The boundary's Case plus the Case journal header's scope/Result must match the actual ResultRow/AssignmentUse/Assignment role origin; a shared payload length is not an identity check.

The loader obtains the actual selected-parent native state and applies the actual persisted transition delta up to this captured length. It checks the resulting root, the actual accepted transaction position and the same Case header event boundary. An arbitrary state with a caller-supplied expected root is not provenance. Missing original boundary or populated input history remains unavailable, including after pruning; it is never interpreted as an empty Case or as a later current P snapshot. The retained populated entries preserve amount, script, coinbase flag and input DAA in input order. Their digest and boundary fee must agree, and checked input sum must equal output sum plus actual fee. Ordinary native Full script validation remains independently mandatory.

First Case journal material is the genuine accepted op9 full native Transaction serialization. Borsh includes the cached transaction ID and atomic storage-mass field. The writer/loader therefore use one immutable actual Full-validated storage-mass serialization, independently recompute the ID from literal consensus fields, reject a stale/bad cached ID, and compare against the actual accepted slot and Case header origin. A deserialized cached `id()` is not independent identity evidence. No synthetic old op0 is manufactured.

For op1 record material, the independent canonical job supplies the exact decode count. Before hashing generated bytes, the helper requires a nonzero expected decode count, raw length exactly `4 * expected_decode` under checked arithmetic, and RecordHeader.result equal to the independently resolved literal Result. Both WitnessRow references use the same actual accepted op1 origin. A hash, supplied RecordHeader or saved WitnessRow alone supplies no A1 terminal, role consent, service receipt or P approval.

The concrete shared helper is `consensus/core/src/palw_positive_assignment_case_material_v2.rs`. Writer and loader must call that same implementation. Candidate tests cover fixed boundary length, changed pre-root/delta position, input/fee bindings, independently expected Result/decode mismatch, changed generated byte, and absence of an extra generated Vec prefix. Until actual complete history, physical/work custody, source replay and native final row checks are connected and executed, these codecs are DATA only and provide no positive native Case session.
