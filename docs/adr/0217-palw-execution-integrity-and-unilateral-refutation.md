# ADR-0217 — PALW実行整合性と一人による反証の完結契約

Status: **Accepted design / ADOPTED_DESIGN_NOT_ACTIVATED**
Date: 2026-11-09
Authority: この会話のユーザーによるRFC改訂と独立エージェントの反復レビューの明示指示。
RFC: [RFC-0049](../rfc/0049-palw-execution-integrity-and-unilateral-refutation.md)
Current owners: [RFC-v2-0016〜0020](../rfc-v2/README.md)

本書は統合後の新規採択記録である。ADR-v2の51冊目を作らず、50冊の本文・歴史付録、既存ADRの採択記録を変更しない。番号0217は添付内で未使用だった範囲の割当であり、未取得branchの予約を保証しない。

## 問題と根拠

ユーザーが求める保証は、Panel本人の実行行為の証明ではなく、一人の正直な検証者が発見した計算矛盾をNodeが小さな計算で確定し、必要な検証が未成立のclaimを成功させないことである。

添付設計には、承認閾値と単独異議の優先関係、同blockのFinal競合、初期状態から終端までの局所反証の網羅、攻撃者の予約占有による提出阻害の規範的な不足がある。多数の承認を集めるだけでは、この重大な認証・裁定の不足は解消しない。runtimeの既知脆弱性が再現されたという記録とは区別する。

## 決定

[RFC-0049](../rfc/0049-palw-execution-integrity-and-unilateral-refutation.md)と[PRINCIPLES §13](../PRINCIPLES.md#model-free-adversarial-verification)の限定改定を採択する。詳細の通常編集先は20冊を維持する。

- Miner署名の実行記録に初期条件・全遷移・終端条件を結び付け、全relation familyを有界なnative裁定へ接続する。
- 一人の適格noticeをnative未解決状態へ反映し、多数の肯定承認でも上書きしない。一人の有効な反証は肯定数不問で無効化する。
- 認証、適格異議、裁定、期限、依存、経済効果の順序を固定し、同blockのFinal先行による取り逃しを許さない。
- 資料未供給、検証未完了、native計算不正、客観的な提供義務違反を別の状態・責任として扱う。
- 一人の合法な反証経路に必要な費用・予約・配送・包含・復旧前提を明示し、悪意側の先着予約だけで排除しない。
- 本人のGPU使用、非外注、全Panel共謀時の無条件正当性、任意の永久検閲下での完了を保証しない。

## 比較した案と不採用理由

| 案 | 判断 |
| --- | --- |
| 肯定票の閾値だけを上げる | 一人の反証の到達・優先、関係網羅性、資料不足を解決しない |
| 一人の私的な取得不能申告を算術有罪とする | 通信障害や虚偽申告を計算不正と混同するため不採用 |
| 少数の正しい局所計算を全体証明にする | 未検査箇所の誤りを排除できないため不採用 |
| 資料不足時にNodeが全モデルを取得する | Node非保有・有界裁定の採択条件を破るため不採用 |
| 反証が未完成なら期限で成功へ進める | 必要な検証未成立を成功へ変換するため不採用 |

計算の暗号学的証明の禁止は維持し、その代替案の採択・研究再開を本記録から導かない。

## 適用範囲と移行

新しいclaim/profileに限る。旧claimの署名意味、旧Gate C、既存のPositiveChecked、wire・fence・稼働設定を変更しない。ADR-0215と公開裁定v0.2は過去の採択記録として保持し、今回の新profileについてだけ[公開裁定v0.3](../design/palw/consensus/public-adjudication-policy-v0.3.md)と改訂16〜20が補う。ADR-0216のEXEC・1 BPS、PRINCIPLES§8/§9/§14、既存パラメーターは維持する。

## レビュー・検証・残余条件

独立エージェントのレビュー結果と修正反復は[今回の改訂](../maintenance/revisions/2026-11-09-palw-execution-integrity/README.md)へ記録する。本採択を根拠にレビュー未了をPASSに変換しない。仕様整合・抽象モデル・文書保全と、実装・実測・有効化の判定を分ける。

残余条件は、認証の暗号仮定、規範の決定性とrelation網羅性、正直な一人の能動的検証、必要資料、資格と有限費用、期限内のcanonical包含、合意ノードの規則実施、保護された資源容量である。正しい反証がない場合の全体肯定承認にはglobal検証者の誠実性の前提が残る。

不成立時は受理・activationを閉じ、既受理claimは原時計に従って成功停止・未検証終了・残存責任を処理する。資料不供給だけを算術不正と決め付けない。消費済みEXECの全取引を、この改訂だけで一括巻き戻す規則は設けない。
