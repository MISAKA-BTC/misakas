# ADR-0014 — EXEC・共通容量・難易度・合意時計を選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**DECISION_RATIONALE**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0014](../rfc/0014-exec-schedule-and-capacity.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

claim数、外側carrier、EXEC、Court、乱数controlを別々に増やすと、総負荷と発行量が無制限になり得る。また、heartbeatで時計が進むことと、実仕事が認証されることは異なる。

## 決定

EXECは認証済み仕事に由来する有限の権利とし、事前scheduleと全kind共通の搬送容量に従わせる。新規受付より既受理Court・controlの必要容量を保護する。難易度、時計、発行、失効、優先処理はRFCを正本とする。

## 判断理由

- 合意に必要な仕事が増えた場合にも、Nodeの処理上界を維持するため。
- 大量の新規claimで既受理の反証機会を使い切らせないため。
- heartbeatを認証済み仕事や経済需要の実測へ混ぜないため。
- schedule公開後の有利な再配置を防ぐため。

## 比較した方針

laneごとの無制限な追加BPS、落選仕事からの別credit、事後的なschedule選別、当選しないclaimの反復再評価は採らない。clock進行だけで決済を強制する方式も採らない。

## 帰結

carrierの目標頻度と個別claimの認証遅延は別になる。高頻度blockを作れても決済目標の達成を意味しない。受付制御には仕事供給・Court backlog・資本・保持資源を含めた較正が必要となる。
