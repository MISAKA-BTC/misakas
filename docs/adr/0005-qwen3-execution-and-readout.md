# ADR-0005 — Qwen3の整数実行・37-vector Readoutを選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**DECISION_RATIONALE**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0005](../rfc/0005-qf1-qwen3-execution-profile.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

「LLM内部状態をReadoutに使う」という抽象記述だけでは、どの位置・層・演算後の値を照合するかが実装ごとに変わる。既存Qwenの回答能力を利用しながら、採掘専用の無関係な重い計算を足すことも避けたい。

## 決定

特定のQwen3 instanceを、固定した整数profile・入力frame・生成規則・実推論中のReadoutとして具体化する。architecture、数値幅、対象vector、trace codec、hash式と境界値はRFCへ置く。

## 判断理由

- 実際の推論で発生する状態を読み、付属IDだけに採掘の根拠を置かないため。
- GPU・CPU・低RAMbackendが同じReadout境界を実装できるため。
- 位置、Stop、hash chunk、元tensorの間を局所Courtで照合できるため。

## 設計選択の補足

抽象的な層数の例では実装境界が決まらないため、特定のQwen3-8B構成を採用する。実際の層・演算・state producerへReadoutを結び付けるための選択である。



全層に同じ便宜的な量子化scaleを当てると、元のモデルの品質を損ない得る。scaleを不変model parameterとして登録する選択は、再現性と層ごとの数値範囲を両立させるためである。



このprofileでは生成分岐の自由度を限定し、Minerと検証者の再現性を優先してnon-thinking frameとgreedyを選択する。品質上の影響を許容できるかは別に評価する。

## 比較した方針

回答文だけの利用は、同じ短い回答の予測・再利用という問題を残す。全乗算のprefixを常に採掘traceへ追加する案は、記録処理自体を仕事の中心にし得る。任意のXORや追加暗号パズルを層へ挿入する案も、有用推論との関係を弱めるため選ばない。

## 帰結

整数化した実行の品質は元の浮動小数点実装と別に評価する必要がある。Readoutを具体化してもG-COLL/G-COSTの保証は自動的には得られず、BFT採用はその不足を証明済みへ変更しない。
