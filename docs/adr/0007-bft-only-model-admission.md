# ADR-0007 — BFTだけのモデル追加・採用を選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**DECISION_RATIONALE**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0007](../rfc/0007-bft-model-admission.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

モデルの構造検査や有限の測定だけで、将来の安価な予測法をすべて排除することはできない。自動検査と人の判断の二経路は、何が採用を認可したのかを曖昧にする。

## 決定

モデル追加はBFT YES/NOだけに統一する。kernel解析・lowering・codec検査は実行の技術条件として残す。票の有効条件として数学的証明・品質証明・一律ベンチマーク合格を要求しない。投票形式、集合固定、定足数、状態遷移、拒否条件はRFCで規定する。

## 判断理由

- 採否を認可した主体とscopeを一つにするため。
- 実用性や未知の高速化について、有限試験を普遍的な証明として扱わないため。
- 未対応kernelをBFTの裁量で実行可能にすることも避けるため。
- 全モデル共通の管理・経済へ接続するため。

## 比較した方針

kernel自動PASSによる採用、timeoutによる採用、BFT不成立時の自動経路fallbackは廃止する。証明書必須の採用は今回のユーザー方針に合わない。一方、YESだけで技術的不正を免除する案も、Nodeの決定論的実行を壊すため採らない。

## 帰結

採否にはBFT参加者の判断と故障前提が入る。UNKNOWNはUNKNOWNのままであり、採用票は計算困難性の定理にならない。個別claimのPanel・Court・Gate Cを引き続き必要とする。
