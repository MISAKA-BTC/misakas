# ADR-0011 — 独立Gate C・合意credit認証を選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**DECISION_RATIONALE**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0011](../rfc/0011-gate-c-and-consensus-credit.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

閉じた参加者だけが承認したclaimや、異議が出なかっただけのclaimをそのまま合意weightへ変えると、必要な独立検証が行われないまま台帳の影響力が生じ得る。

## 決定

claim Finalと独立した仕事認証を分け、合意creditを使う入口にGate Cを置く。選出・検査義務・認証述語・失効・各consumerのgateはRFCに定める。

## 判断理由

- 手続きの終了と、合意へ使う信用の獲得を区別するため。
- Minerの自己申告や同じPanel票だけでfork choice・支払いを進めないため。
- producer、validator、RPC、IBDが同じ資格判定を読むため。

## 設計選択の補足

閉じたモデル保有者だけの承認や、反証が出なかったという事実だけでは、独立した検査機会を確認できない。このためFinalから合意資源へ進む境界に独立Gate Cを置く。

## 比較した方針

Finalだけ、一致したlocal replayだけ、BFTモデル採用票だけを合意認証とする案は採らない。G14の一人の正直Panelという仮定も、独立認証の正直割合を代替しない。

## 帰結

認証待ちの遅延と再実行費用が増える。抽選位置が多くても同じoperatorに集中する場合があり、位置数を独立人数として表示できない。故障比率、資料取得、包含、活性を別々に評価する必要がある。
