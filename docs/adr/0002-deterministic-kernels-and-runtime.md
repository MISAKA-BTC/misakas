# ADR-0002 — 決定論的kernel・GPU・低RAMランタイムを選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**DECISION_RATIONALE**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0002](../rfc/0002-tensor-ir-kernels-and-runtime.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

GPUや低RAMでの実用推論と、Miner・Panel・Courtが同じ結果を読むことを両立させたい。機器ごとの丸めや演算順序を規範にすると、正しい実装同士でも結果が食い違い得る。

## 決定

PALW-TIRの意味論を規範とし、CPU・GPU・streamed実行をその実装として扱う。モデル拡張は有界なkernelと局所checkerにより行い、任意VMへのフォールバックは置かない。算術規則、状態更新、observer、資源予約の具体仕様は対応RFCへ集約する。

## 判断理由

- 最適化の自由度と、合意値を変更する自由度を分離するため。
- 大きなモデルを使うためだけに全重み・全traceの同時RAM保持を要求しないため。
- 新しい演算を登録する際に、局所反証の経路とNodeの最悪資源量を確認できるため。
- kernel対応をモデルの自動採用や計算困難性の証明へ読み替えないため。

## 比較した方針

汎用VMは拡張範囲を広げるが、実行・メモリ・争点・資源の検証範囲も拡大するため採らない。機器固有の近似結果を多数決で承認する別familyも採らない。同じ数値意味を返す最適化backendと有界tile処理を選ぶ。

## 帰結

未知演算にはkernelとcheckerの追加が必要であり、BFT YESだけでは実行可能にならない。低RAM化は転送や再読の費用を増やし得るため、GPU速度、peak RAM、disk帯域、trace費用を別に測る必要がある。
