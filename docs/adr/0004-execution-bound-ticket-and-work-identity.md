# ADR-0004 — 実行依存Ticket・仕事の一回性を選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**DECISION_RATIONALE**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0004](../rfc/0004-fow1-execution-and-ticket.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

実行前に決まる値だけから当選を調べられると、落選試行のLLM計算を省略できる。また、同じ正しい結果へ別nonceや任意metadataを付けるだけで採掘機会が増える構成も避けたい。

## 決定

FOW1では、試行固有の実入力、規範実行、Readout、canonical commitmentとTicketを一つの契約へ結合する。同じ仕事の認証と消費は用途ごとに一回だけ計上する。式、符号化、alias、消費規則はRFCを正本とする。

## 判断理由

- 当選判定を、実行と無関係な安価な識別子から切り離すため。
- 正規出力を固定した後の再符号化や署名の変更で抽選回数が増えないようにするため。
- 複数carrier、prefix再利用、reorgをまたいでも仕事の由来を追跡するため。

## 比較した方針

IDの非衝突性だけをPoW費用の根拠にする案、全traceを書いた量を通常LLMの実費と同一視する案、出力一致から通常手順の実行を断定する案は採らない。内部状態をTicketへ束縛する設計を選ぶが、その値を安く求められないことは別の評価・仮定として残る。

## 帰結

正当性・非衝突性・新規計算費用は別の保証になる。正しい高速化を算術不正としてslashできるとは限らず、モデル採否や停止の判断と区別する必要がある。
