# ADR-0013 — モデル別仕事量・報酬・EXECの接続を選ぶ理由

- 文書日付：2026-11-26（Asia/Tokyo）
- 文書区分：**PROPOSED_DECISION_NOT_ACTIVATED**。判断の背景・理由・代替案・帰結を記す。
- 対応仕様：[RFC-0013](../rfc/0013-model-work-accounting.md)。数式、形式、状態遷移、受入条件と提案部分の区分はRFCを正本とする。
- 進捗・実装完了・公開有効化を示す文書ではない。新たな採否は明示的な決定を必要とする。

## 背景

同じ一promptでも、モデル、context、出力長、MoEの実稼働部分などで規範仕事量が異なる。一律報酬だけでは仕事の差が反映されず、parameter数だけの倍率にも限界がある。

## 判断案

共通meterによるModelWorkProfileを使い、認定仕事量を報酬原資と有限EXEC生成権へ結合する。共通targetと仕事比例の当選原資を組み合わせる案を選ぶ。具体式、演算表、予算と較正はRFCの提案仕様に置く。

## 判断理由

- モデル名やBFTの任意単価ではなく、同じ規則で仕事を比較するため。
- 当選確率と報酬の両方へ同じ倍率を重ねる二重加重を避けるため。
- 規範計算量、実機費用、検証費用、Node資源を混同しないため。
- 重い仕事から発行するEXEC量も、共通発行・資本上限の中で有限にするため。

## 設計選択の補足

標準Jobを固定してtargetを仕事量比例にする選択肢もあるが、自由な生成長とFOW1の事前固定targetを同時に扱うには追加条件を要する。MWA1は共通targetと仕事量比例の当選原資を提案し、二つの方式が混在することで仕事量を二重評価することを避ける。この選択自体も提案段階である。

## 比較した方針

| 方針 | 判断理由 |
| --- | --- |
| promptごとの一律報酬 | 実行量の違いを反映できない |
| 総parameter数による倍率 | 稼働expert、停止位置、context、量子化を十分に表せない |
| BFTがmodel単価を自由に決定 | 比較可能性と共通発行上限を弱める |
| 出力を見た後にtargetを変更 | 試行前固定の条件を壊す |
| 仕事をtargetと原資の両方に加重 | 期待報酬が二重に増える |
| 共通targetと認定仕事比例原資 | 提案として選択。全額予約と上限内の較正が必要 |

## 帰結

**このADRは提案であり、再編によって採択しない。** 安価な正しい算法の不存在、実機採算、目標block頻度や決済時間を保証しない。モデル採用のBFT票もその証明ではない。
