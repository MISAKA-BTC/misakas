# RFC29/32 retryable staged TIR filer journal — 2026-10-25

Status: parent-coordinated node build and focused runtime PASS. Filter `tir_filer_journal` ran 6/6 outer tests in 0.30s, including the isolated quota child (1/1, 0.10s; not an additional independent test). Build completed in 1m49s. No Cargo launched by this agent.

The original journal loader multiplied the 90,000-byte single-control ceiling by sixteen, even though a staged finding may span multiple controls. It could persist a legitimate larger finding then quarantine it at restart. The public evidence Borsh Output decoder also has a 20,000-ID single-control bound, while staged Output shape permits more. IO or admission failure returned an apparently empty book, which could later overwrite the still-existing old journal.

The new private journal codec preserves the exact magic and count/entry/variant/field bytes. It changes no public carrier decoder, cap or native authority. Its local staged Output branch reads the same count/IDs under an actual file/typed-heap preflight, without borrowing the single-control ID ceiling. The allocation-free root scanner checks the existing maximum sixteen entries and walks the actual nested evidence schema before Borsh allocation. Duplicate claim keys are not a legitimate map encoder output and are rejected. Shape checking has its own second complete typed-body scratch envelope, separate from the decoded storage it may clone.

The reader opens one regular file, stats its exact length, and admits the typed byte buffer in both native and host ledgers before fallible reserve/read. It reads exactly that length, checks one additional stack byte, and checks the opened file/path identity, length and modification stamp again. Growth, truncation or replacement observed during the read returns Changed/IO for retry, without quarantine. Only stable malformed syntax is set aside after another handle/path check. There is no invented whole-journal policy maximum: an address-space/arithmetic/real local-capacity refusal holds loading. This is a local single-service file protocol; it is not a claim of atomic compare-and-rename against an uncooperative external writer.

A loaded book now remains explicitly loading on IO/resource failure. New queue publication and persistence are blocked while loading, and both the actual outside-owner tick and actual filer tick invoke the same retry/dirty-persist maintenance before pursuing or filing. Retry reading runs in a blocking worker whose raw/decoded resource owners live through cancellation. The book retains its JoinHandle and awaits it by mutable reference: cancellation preserves the same in-flight worker and its eventual result; only a terminal await removes the handle. Book drop can detach that worker, whose own resource owners still remain valid. Dirty persistence retries even without a new finding or chain event. Encoding uses a borrowed map serializer and an exactly preadmitted byte Vec for magic plus body; it creates no entry-reference Vec, Borsh initial/growing intermediate body, or concatenation copy. Dirty clears only after successful temporary write and rename, leaving old primary bytes intact on failure.

Reloaded payload quota is pooled and referenced only by sidecars of the entries loaded from it. Removing the final loaded entry releases that aggregate deep-payload quota even while the book remains alive. A separate book-level metadata ticket covers the retained sidecar Vec capacities and BTree/Arc allocation envelope, including capacity after remove/clear. It may conservatively retain node/header overhead until replacement/book drop; it does not retain the whole retired deep payload. Field order drops actual pending values before their resource holders and sidecar buffers before the metadata ticket. No serialized owner flag/token becomes current claim, duty, source, signer, fee or payment authority; every actual send still uses current native preflight.
