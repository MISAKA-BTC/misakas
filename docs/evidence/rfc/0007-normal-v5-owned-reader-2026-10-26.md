# RFC-0007 normal V5 source reader: typed ownership boundary

The existing V5 source path still carries several `String` readers. In particular, a local resource refusal inside the native ledger or Final projection could be converted into a semantic source refusal. The new `palw_paid_normal_source_owned_v1` module retains typed authority, target, Final, source and promise readers while preserving the existing V5 collector and ordering. It does not change any activation, approved policy, source independence rule or selected-verifier approval criterion.

The module is compiled in the ordinary `kaspa-consensus-core` library. The ordinary paid-check authority branch now calls its retained V5 material reader; seeded and explicit V6 branches keep their own existing readers. This is a typed resource boundary, not a new source-selection or approval policy. The accepted native Panel V5 source test compares its returned contract, source inventory and promise inventory with the existing reader and all three match. That tests one accepted Panel route; it does not establish a successful ClaimVerification normal-source route.

Type check: `cargo test --offline -p kaspa-consensus-core --lib --no-run --config profile.test.package.kaspa-consensus-core.opt-level=0` passed on the test-only import of the same source. The production import also compiled. `rfc0010_production_fold::paid_panel_sources_hold_the_same_native_r_until_actual_final_fee_queue_and_survive_replay` passed with `RUST_MIN_STACK=67108864` after the default test-thread stack aborted with stack overflow. The source/value comparison reached its assertions and passed; the default-stack abort is not a V5 value mismatch. The builds used shared `buildslot.sh`; diagnostic logs are `/private/tmp/rfc07-owned-typecheck-20261026.log` and `/private/tmp/rfc07-owned-panel-parity-20261026.log`.

After connecting the ordinary paid-check branch, `paid_check_authority_` passed **5/5**, including actual native Receipt/FS folds and a local initial-authority identity/corruption test. The latter inserts a frozen target into a private fixture; it is not native source-target admission. The compiled unit test binary passed the full `paid_claim_reader_v1` filter **16/16** (including those same five). The relevant build log is `/private/tmp/rfc07-owned-check-consumer-20261026.log`. These checks do not exercise a successfully funded normal ClaimVerification source through a real node, quota at every nested reader, independent source operators, all four adapters, restart/pruned IBD, or a public campaign.

Capacity remains incomplete. Validator scratch, the V5 collector's internal worksets, and Panel authority's old `String` boundary are not owned by this module's output leases. Current canonical Final events have empty profile dependencies; a future event with nonempty dependencies needs a new nested-heap quote. The tested equivalence cannot turn `source independence`, four adapters, historical signatures or the 15-gate campaign into PASS.
