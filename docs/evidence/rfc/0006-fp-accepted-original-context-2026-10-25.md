# RFC06 FP replay initial context from the accepted original — 2026-10-25

Status: parent-coordinated node build and the two focused runtime controls PASS. This record is not a full-activation or RFC12 campaign result.

The active routing replay caller previously used the decoder ceiling when no authenticated capture supplied the exact executed context. Early stopping can make that context differ from the native claim pin. The caller now reads the original commitment through the same guarded native session's accepted-data index and owned block body. Missing/pruned bodies or a missing original hold the job for retry; they never authorize the ceiling context. The inactive path is unchanged.

The reader checks the indexed transaction ID/current hash and FP subnetwork, locates plain/TFP1/HFP1/TFO1 originals (including an outer accounting FPA1), and uses the existing bounded codec preflight and retained decoder. It separately reserves a checked growth envelope for the full commitment's Borsh claim-ID hash scratch before hashing. The full claim ID, served job, class, executor, execution/trace/output roots, work leaves and native job pin must match. The backend constructs the context from the original's executed count, and the resulting context is retained. The replay factory then performs its existing fresh native binding before the original backend/owner reaches the worker. No new core API, wire schema, policies or presets are introduced.

The original commitment includes the executed count in its claim ID. Recovering that immutable descriptor does not select an RFC38 winning answer carrier, transfer payment/fee authority, establish verifier approval or prove correct execution. Original and derived allocations retain separate reservations; role-memory pricing borrows the bound retained context instead of making an unreserved context clone.
