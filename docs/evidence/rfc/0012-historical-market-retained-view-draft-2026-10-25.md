Status: phase-1 Core owner and internal VP reader are registered and source-complete; parent-coordinated compilation/runtime are **PENDING**. Public ConsensusApi/session, node and simulation are not connected. This does not complete historical market RPC support.

## Exact state and retained ownership

`walk_chain_path_retained_v1` reverses removed deltas then applies added deltas including the target. The state at A is **after A**, matching the post-A EVM snapshot and the existing `EthCallEnv` head-own-view contract. The finalized-material reader passes parent(finality) for a different reason: a header commits its selected parent's state. This reader requires `last_point.block == A` and never authenticates post-A state against A.header's parent-state root. Genesis retains its established no-last-point exception.

The internal VP entry owns the actual reader-first pruning session throughout the read. SessionLock's documented recursive-read behavior permits an outer Consensus session to delegate safely; no writer-preference assumption is used. Import session/stable markers are read directly from their typed meta store and rechecked after replay. Store, genuine missing history, resource refusal with/without a numeric quote, native context and other reachability/walk causes are distinct. A changed import epoch or unfinished import cannot return an owner. It does not return latest state on any failure.

Removed transitions reverse in streaming order. Compact selected-parent rows count the forward path before its Hash vector is reserved and allocated, then forward deltas apply under retained state/delta owners. Brent identity cycle detection covers corrupt self/two/long cycles without a growing visited set or assumptions about DAA/blue-work increase. Metadata-store internal allocation behavior is not newly claimed as fully quota covered.

Core's `evm_view_quote_v2` borrows actual source tables without allocation. The public construction method exists only on `NativeRetainedV1<PalwChainStateV2>`; its bare-state helper is private. It reserves output plus scratch while the input state owner is live. Explicit vector capacities cover class/root and line/name arrays and grouped proposal/evaluation arrays; typed BTree envelopes cover the version/group/market/position/refusal trees. Root capacities are bounded by class+version counts. The temporary line tree and group-count indexes coexist with the output and have separate scratch demand. Construction transfers the persistent reservation to `Arc<NativeRetainedV1<PalwEvmViewV1>>`, drops scratch, then returns the owner. These are logical requested-allocation envelopes, not physical RSS or a campaign guarantee.

## Meaningful phase-1 controls

Core filter `historical_evm_view_` has four tests. A dense historical projection fixture fills every dynamic output collection, including named lines, versions, grouped declarations, markets and positions, and compares the owner with the old raw payload. Quote growth follows an actual extra row. A compatibility matrix covers all four class statuses, current lifecycle variants, four gate flags and present/base/absent classes. Independent fixed golden refusals also check missing class, inactive class before registry, exact Probation/Held/no-row reason strings, dormant audit and absent registry; verification is not solely the same common helper called from both sides. A child-process logical limit rejects Q-1 before builder entry, permits Q while a separately retained input is live, retains demand through another Arc, and recovers all demand on final drop. These are projection/ownership fixtures, not native registration/approval.

Consensus filter `evm_asof_` has six tests. Four use the actual skip-PoW native pipeline/internal entry: accepted A versus its accepted parent, exact header DAA and old raw view equivalence; a real branch switch followed by exact old-A reconstruction and genuine deleted-delta refusal; corrupt selected-parent cycle metadata reaching the actual reader; an actual `begin_pruning_point_import` between walk and recheck, then incomplete-import refusal; cold malformed reachability and sync-marker rows versus true absence; and an isolated zero logical budget returning Resource. The cycle's extra compact row is deliberately corrupt, unaccepted storage metadata, never an accepted fact. Destructive history/metadata and isolated-capacity controls gracefully stop only their own fixture workers after actual native acceptance, so an unrelated background convenience reader cannot race an intentionally corrupt row; these are then actual prebuilt-store queries, not restart evidence. Two helper controls cover cycle sequences and preservation of actual wrapped reachability error variants. Child subprocesses are inclusive parts of their parent test, not extra acceptance counts.

These tests do not execute EVM transactions or provide K3/campaign/claim certification evidence. They are source only until the parent records actual results. New leaf formatting, production parse-to-stdout and diff checks passed. Cargo was not launched by this worker.

It must derive registry-presence exactly as the existing resolver (registry fence plus execution lane) and test that projection against it. Phase 1's internal state entry is not a replacement for that outer API contract.

No raw Arc plus detached sidecar ticket is acceptable. This API/node/simulation connection and actual frozen-tier registration/read-precompile controls remain unimplemented here. Formal native39 settlement mapping and K3 inputs remain unavailable and are not synthesized.
