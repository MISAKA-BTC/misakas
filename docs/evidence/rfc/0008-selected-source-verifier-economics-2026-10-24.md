# RFC-0008: private selected-source verifier economics (aux146)

## Scope and authority

This record describes a new native aux146 schema and its explicit private input. It does not approve an economic policy or activate a public network. The public presets retain `None`; normal startup rejects armed selected-source economics. The R ceiling supplies accounting limits, never money. Existing aux139 router rows and old action tags 0/1 retain their meanings; new funded actions append tags 2/3.

## Connected lifecycle

The native source producer's signed terms debit actual available collateral before approvals. The immutable whole-epoch governor binds the network, bootstrap policy, fixed epoch, inclusive liability horizon and explicit count caps. Prepayment covers the distinct drawn actors, even when one actor occupies multiple weighted slots. An approval creates one actor/work duty, one aggregate collateral hold and an independently R-limited source-income reservation; R is not the source of the prepaid fee. Each hold delta also updates the existing primary `reserved_exposure` ledger through its typed journal writer. Every common native collateral and exit predicate therefore sees the duty without a new fallible auxiliary lookup or a second charge.

Both native object application and the native closing tick feed their deterministic `Convicted` events into the duty court bridge. Within the inclusive horizon that bridge charges the checker's available collateral once, releases its explicit hold, cancels its income reservation, and records the forfeited fee and collected amount. Merely passing the horizon without a successful tick does not release a hold.

After the inclusive horizon, indexed due-work processing releases surviving holds. A fee is queued only for a historically selected-approved source which the current native ledger also considers settled and unconvicted. Missing settlement cancels that fee entitlement and leaves the amount available for principal refund. Queue saturation defers the unallocated amount. Unused prepayment returns to the sponsor and is not R income; zero approvals can therefore refund without an R engine.

The common deterministic payout-prefix drain invokes a dedicated observer before the budget tick. It checks the actual journal's deleted payout, original payload, queue/receipt identity, amount, block and DAA. It records payment acknowledgement only after an earlier block queued it; the next block may have the same DAA. The total `queued` and `refunded` fields are cumulative allocations and are not decremented when acknowledged. Pending queue indices are removed, so later ticks cannot pay the same entitlement again.

## Resource and restoration boundaries

Actions use fixed-key and ordered-prefix readers. Court lookup uses claim-to-duty indices, release uses horizon/work indices, and diagnostic collateral lookup uses an actor aggregate. Native admission reads the existing primary exposure ledger. Dormant absence of aux146 requires no new allocation. Encoding, key storage, journal growth, typed decoding and temporary indexed-reader/workspace allocations are reserved before the corresponding ownership is created. Local resource failures remain local resource failures.

Cold restoration checks the namespace against its explicit policy, actual governor counters, bidirectional indices, source approval identities, aggregate actor holds, funding conservation, terminal entitlement framing and pending payout backing. The validation uses bounded linear passes and separately reserved aggregate maps, rather than scanning all liabilities for each actor. The common exposure rederivation adds aux146 aggregate holds under a returned reservation ticket retained until the accumulator is dropped. Conviction restoration rejects collected amounts above exposure and requires the same conviction/forfeiture/receipt block. Journal replay and reversal remain the reorg mechanism; no policy default or replacement authority is inferred from remote bytes.
