# RFC-0018: モデル別ブロック生成と DAG 統合の検証 — 2026-10-31

対象は [RFC-0018](../../rfc/0018-dag-parallel-multi-model-consensus.md) の主目的である、モデルごとの独立したブロック生成と、並行・遅延到着した仕事の DAG への取り込みである。設計、有効化高さ、DAG 幅の値、モデル階層は変更しない。

## 実装の接続

- producer は `--palw-producer-class <128-hex class-id>` で生成対象を選ぶ。各モデルの miner は別々の bond/key と node で同時稼働できる。非 floor の実行にはそのモデルの `--palw-class-artifact` も必要。起動・資金設定は [参加手順](../../operations/mining/testnet12-join-mining.md) に従う。
- 通常の template は複数 tip を親に取り込む。PALW の merged-work fold は BLUE/RED の両方を検査し、claim の元の model、bond、carrying block を保存する。
- `palw_dag_sibling_attribution_v1` の下では、共有予算の採用順がモデル間 round robin になる。selected parent で既採用の仕事を巻き戻す仕様ではない。
- DAG 幅の reader は `k`、親数、mergeset、merge depth を選択親の保存済み DAA で切り替える。header、template、GHOSTDAG、pruning proof の経路に接続済みである。旧文書の「stub / reader なし」は 2026-10-15 時点の履歴である。
- 全モデルで claim 単位の Gate C を維持する。モデル階層は genesis/年次指定 1.0、登録 0.3 という固定の経済係数であり、モデルの審査は導入しない。

## 今回追加した検証と修正

`rfc18_a_delayed_model_joins_without_stopping_other_models_and_survives_restart_and_replay` は、同じ親から 3 モデルの block を作り、3 番目を未配送にする。他の 2 モデルを取り込み、そのうち 1 モデルの次の claim まで生成・受理した後、遅れた block を配送する。通常 template の join、実際に RED になった sibling の claim 帰属、同じ RocksDB での停止・再起動、遅れた sibling を先に配送する別 node への full-block replay、その後の継続生成を検査する。

これは実 consensus pipeline の試験である。ただし、推論結果の root とモデル readiness は fixture、PoW は skip、時計は simulated であり、実モデル推論・実プロセス間 P2P の測定ではない。再起動後は readiness を植え直さない。full-block replay は pruning snapshot からの IBD と区別する。

実プロセス用 `rfc0018_dag_drill.py` は現行 RPC との不整合を修正した。

- `getPalwClaims` を executor bond ごとに呼び、terminal claim を含め、欠落・truncated を成功にしない。
- `getPalwFenceSchedule` の `viewJson.fences[].armed` で fence を確認する。
- 同じ sink だけでなく claim の全レコード、pinned carriage の state root、settlement を比較する。
- Panel は `assignments[].claimId/classId/seats[].seatId` を検査する。異なる集合であることと、集合が互いに素であることを区別する。
- sibling の direct parent 集合の一致と、複数 join block をまたぐ実際の祖先関係・GHOSTDAG 帰属を確認する。最終 mergeset に見当たらない block を無条件に `IN_PAST` にしない。
- 1 本の接続の A→B と B→A の両方に plan の配送遅延を適用する。従来は mesh が A→B の接続だけを作るため B→A の指定が無視されていた。
- honest sibling の void を成功とせず、観測した完了段階を `licensed` と明記する。これは認証・支払いの実行結果を意味しない。
- 攻撃試験の未取得メトリクスを 0 とみなさず、測定不能として `BLOCKED` にする。空の攻撃 claim 集合も成功にしない。

## 有効化と残る受入範囲

本作業は新たな fence の有効化を行わない。現行 shipped testnet-12 の Gate C は DAA 17,400 の既存設定であり、sibling attribution、permissionless anchor、rule E participation v2、DAG 幅の schedule は別の fence である。Gate C の有効化だけから、それらも有効だと扱わない。

RFC §14 の実プロセス試験 T-0f / T-1e / T-3c / T-3d、実モデルでの認証・本人への支払い・負荷計測は今回の記録では未実行である。特に現行 claim RPC は攻撃者別の全 credit メトリクスを公開していないため、driver は不足分を `BLOCKED` と報告する。RFC 全体の受入完了・本番有効化と、モデル別生成と DAG 統合の pipeline 検証を区別する。
