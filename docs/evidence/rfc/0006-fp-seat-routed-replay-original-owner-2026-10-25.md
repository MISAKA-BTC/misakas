## Concrete defect

`fp_seat_replay_pass_v1` resolved a backend, bound own native claim routing to it and saved it in `routed_backend`. Its absent-task branch then independently resolved another backend and passed that second instance to `replays.start`. Thus the actual worker did not receive the backend that had been bound. On later polls it constructed a fresh native authority instead of retaining the authority under which the executed work had started. The compiler's unused `routed_backend` warning reflected this real disconnected consumer.

## Production connection

The active path now resolves one claim-specific backend, quotes context scratch before extracting an accepted exact-count context, and wraps that same backend with its original native claim authority. An authenticated capture may supply the job spelling already bound by the accepted FP pin; it never supplies authority. The worker receives the entire bound wrapper, with its original native job copy and owner, rather than resolving again. The ordinary inactive path retains its historical execution behavior and makes no new native routing read or scratch admission.

The new routed task output carries the result and the same original Arc guard. It follows the actual blocking worker, detached handle and done cache. Host replay workspace stays in the blocking worker until execution ends; native job/authority reservations stay with the result until the cache entry retires. The node quotes its job copy, guard shell/Arc and context scratch before their allocations. The backend's actual returned capture context must equal the original full job before its roots are exposed to the normal replay verdict rule.

Before a successful cached replay can feed a seat verdict, the consumer reads its own current native claim authority using that original claim/job. Original Some requires the same accepted claim/stamp/job/import identity, using the existing `same_claim_v2` rule, so normal forward containing snapshots remain possible. Original None is recorded explicitly and requires current None. A formerly unqualified cached execution cannot acquire a later routing authority. A legacy cached result without an original marker is refused when the routing fence is active.

Read errors remain retryable and preserve the original done result/owner. A known identity/import mismatch removes only this cached execution so a later pass may execute again under a newly obtained authority. It does not declare an invalid claim, confiscate funds or turn local replay into consensus approval. Other task variants, their slot/timing/retry behavior, and the selected-verifier requirements are unchanged.

## Executed focused controls

Filter `fp_routed_replay` contains three passing controls:

- A synthetic native FP claim/stamp is restored through public checked carriage APIs and used with the actual public `PalwNativeRoutingClaimAuthorityV2::from_native_claim_v2` constructor. A recording backend receives the exact original Arc at bind and checks that same instance when the production worker invokes it. It deliberately returns an execution error: no Q36 arithmetic or passing roots are fabricated. The real worker/book path detaches, reattaches and caches this output while preserving the original guard. A real forward snapshot factory preserves identity; read error retains the result; a different factory import epoch retires it.
- A real BASE-0 free-prompt execution passes through the new production bound worker with an explicitly unrouted original marker. Its actual executed context must match the original context; current None permits reuse, read error retains it, and a supplied Some cannot retrofit authority onto that execution. This does not qualify the floor as a registered routed Q36 model.
- An isolated zero-native-capacity process refuses context/job admission before native-read or execution callbacks can run. This is a local resource fault, not a semantic invalidity verdict.

## Remaining limits

This fixes the exact FP worker/backend/native-owner lifetime and pre-verdict refresh path. It does not claim full resource coverage of the existing FP pool's job/material decoding, cache maps, prompt arrays or all other family replay/DA/audit consumers; those legacy boundaries still need their own complete inventory. The existing generic native getter retains its String read interface and is conservatively retried wholesale. An early-stopped accepted FP job may have a smaller exact count than the decoder ceiling. An authenticated capture can provide the accepted spelling; without such a capture, the backend ceiling fallback may fail the native job pin or the final full-context comparison, withholding the replay. Acquiring that accepted actual-count context independently is a remaining liveness dependency; identity is not relaxed to make the control pass. Real Q36 weights, production reader/router execution, native live-store import/reorg campaigns, physical cost calibration, and downstream receipt/carrier inclusion remain unproven by these controls. A matching local replay still cannot replace selected-validator approval.
