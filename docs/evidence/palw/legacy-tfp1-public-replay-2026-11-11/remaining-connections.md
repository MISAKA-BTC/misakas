# Ordinary TFP1 replay consumer boundaries

The remote implementation checks one independent legacy tiled run against
one accepted FP job, exact signed companion, Source and public
program/prompt/tokenizer/output/Trace. It has no approval entry point.

- Native accepted context must be loaded from one authenticated chain view.
  The future durable paired-link writer/reader supplies the FP claim,
  signed companion carrier digest, original ID, source ID, rooted header,
  literal prompt and native-selected prompt form. Do not build that context
  from a downloaded manifest. Use the same recorded profile, paid horizon,
  registered artifact and registered class from acceptance.
- The remote checker takes the concrete loaded TirBackendV1. Existing
  G14 daemon backend resolution and host memory admission are in
  kaspad/src/palw_tir_public_owner.rs:864–898. The remote caller additionally
  needs finite provider admission and temporary disk reservation. For a
  Panel starting without weights, the format-neutral part of
  fetch_public_wide_artifact_v1 can authenticate and assemble the
  registered inventory. The native container binding must be enforced
  independently wherever the selected profile pins literal container bytes.
- Producer support remains separate. Reuse the retained TFP1 capture's
  existing PalwOriginalCaptureReaderV1 and
  TirBackendV1::open_tir_public_capture_v1 in
  misaka/palw/tir/exec/src/node/backend.rs:1540. The reader already checks
  the exact registered Source and provides bounded read-at native
  StepLeaf/StepRun and complete output IDs. A future publisher can export
  the fixed Trace index from the accepted header and checked native
  openings/preimages in existing public Trace paths, under actual
  publication permits and retention ownership. The existing
  publish_public_trace_tile_v1 accepts WidePanelCaptureV2 and therefore
  does not supply these legacy tiles. A small dense fixture can construct
  exact trace tile bytes via TirBackendV1::step_opening, but this cannot
  replace the bounded live reader for folded or large captures.
- The existing stateless_wide_replay_plan_v1 and public_wide_tir_rules_material_v1
  are deliberately separate. The ordinary relation needs an adopted
  format/identity and coverage for original native selection/stop,
  all registered arithmetic/dependency/initial-state semantics, and
  the two distinct public Trace and FP retention obligations. Until
  that contract and native demand/approval/Final consumers are linked,
  the current adapter's Result<(), _> has no signing capability.
- No daemon route currently delivers an authenticated TFO3 paired
  original. The adapter cannot be connected to a production approval
  solely by changing a wide caller or selecting a plan ID from a
  manifest. It can be exercised independently with local signed
  fixtures and a read-only replay of exact saved artifacts once their
  matching public material and provider are prepared.
