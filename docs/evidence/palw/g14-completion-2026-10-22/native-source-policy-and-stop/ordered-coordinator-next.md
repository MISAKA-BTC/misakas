## Actual call sites and two ordering domains

1. `consensus/src/pipeline/virtual_processor/utxo_validation.rs::calculate_utxo_state` visits selected-parent body FIRST, followed by `acceptance_order` merged blocks. Each merged block obtains `selected_parent_utxo_view.compose(&ctx.mergeset_diff)`, then `validate_transactions_with_muhash_in_parallel`. Selected-parent scripts use SkipScriptChecks because previously checked in the exact same context; other blocks use Full. The lock/spend filter applies independently of script-skip. The complete batch may be cleared if actual round fee capacity refuses it. Only survivors enter the loop adding actual transactions to `ctx.mergeset_diff`, `accepted_tx_ids`, fees and acceptance data.
2. The funded candidate diagnostic currently runs in that accepted loop, immediately before `ctx.mergeset_diff.add_transaction`. Its actual Full/cached input origin is sound, but its PALW state is the separately supplied candidate/parent snapshot, NOT state after each preceding PALW object. A producer key/class changed by an earlier accepted lifecycle object must eventually be read from the ordered current PALW fold, not this log diagnostic. Do not promote its result into native install authority.
3. `processor.rs` virtual-chain walk constructs real `point={current header block, DAA, blue, schedule subsidy}` and checks the header's committed PALW parent root against its walked state. It calls `palw_v2_objects_of_block(&ctx.mergeset_acceptance_data, state, current, header.daa_score, &ctx.palw_v2_rent_available_fees)`.
4. `processor/palw_accept.rs::palw_v2_objects_of_block` currently removes EVERY TFO1 carrier before all legacy decoders, independently of history/TIR fences. Keep that closed until atomic admission exists. Replacing a TFO with its embedded legacy FP before successful funded coordination would create an unprotected claim.
5. `palw_v2_accepted_objects_and_originals` → `palw_v2_accepted_objects_and_refunds_inner` rehearses carried objects SEQUENTIALLY against `folded`. Native validation and extras resolution use current `folded`; only successful object application changes it. This is the native location for prospective source/current actor/class/semantic/EOF checks. It is not enough to validate all original candidates against the selected-parent state.
