## 独立検証の ADJUST（値は残し、武装可能な組とはしない）

1. `block_opportunity`: V3 の `validate` は false を拒否し、RFC-0016 V+ は true を拒否する。同じ高さでは両方を武装できない。pin した規則は「V+ が同じ高さ以下なら false、そうでなければ true」。それを許すコード変更は、この pin には入れていない。
2. rights epoch 720 は、t12 bundle の `epoch_length` 1,000 の倍数ではない。V+ は今の bundle の上には武装できない。
3. `ε = 0` は `palw_model_tier_v1` が同じ高さ以下にあるときだけ根拠がある。tier fence は 16,000 の前提を満たさない。
4. legacy evidence horizon は network ごとの `evidence_window_blocks`。t12 の 10,080 を mainnet（12,096,000）に置かない。validator の `≥` 検査は、この pin では追加していない。

## 先行検証が見つけ、この pin が値として直していないもの

- F1: `P_m < 1/720` のモデルは epoch 内で 1 ブロックも出ない。
- F3: miner 側の `S_m` は claim のない assign を数える。分母を縮めた後も、claim なしの希釈の費用は機会費用だけである。κ = 300‰ はその上限を登録 tier にかける。
- F5: Gate C の告発 window（Final + 5,040）と court notice の締切（`a + 3,120`）は別の時計である。U-3（認証まで保留）の決定は残す。待ちの説明は「2 + 3 日」ではなく Final + 5,040 DAA 以上である。
- F6: `W_budget = 720` は 1 日 hold と一致するが、寿命が 10,000 DAA まで伸びる claim では `L ≤ W_budget` は成り立たない。
