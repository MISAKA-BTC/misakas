# Block-body cache capacity correction — 2026-11-03

The default transactions store already uses `CachePolicy::Tracked` in byte mode. Its previous estimator charged 66 bytes per signature script and omitted transaction payload storage, vector spare capacity and spilled output-script storage. This is a default PQ-network mismatch, not merely a rare large-script case: the source's standard ML-DSA-87 P2PKH unlock is 7,226 bytes; its 69-byte output script exceeds the 35-byte inline SmallVec.

The correction measures retained capacities: the transaction Vec backing allocation, input/output Vec backing allocations, transaction payload capacities, signature-script capacities, spilled output-script capacities, and fixed Vec/Arc/container overhead. Inline script bytes remain included only in their containing struct. A read-only `ScriptPublicKey::heap_capacity_bytes` accessor exposes spilled storage without exposing mutation. Immutable shared bodies keep stable weights; separate cache references to one allocation can conservatively count it more than once.

The existing cache uses this weight when inserting and evicting. At ram_scale 0.3 the transactions budget is approximately 12,000,000 bytes plus its existing small policy noise, with min_items zero. A record larger than that budget can remain on disk and be returned to its caller while being omitted from the cache. Eviction changes caching performance, not body persistence, transaction IDs, serialization, block validity, model results or claim approval rules. No new admission ticket or resource-error path is introduced.

Regression fixtures use the production PQ script builder and standard output factory, compare identical serialized bodies with very different spare capacities, and exercise the actual DB-backed byte cache. They check oversized bodies release their sole cache owner, cold DB reads remain valid, and eight large bodies under a two-body byte budget leave only two live in-memory cache owners. Tests await the parent's centralized Cargo run; no heavy build or remote operation was performed for this patch.

This fixes the byte weight used by this cache; it does not establish that its payloads account for the observed 10 GiB anonymous RSS. Allocation before cache insertion, RocksDB memory, other external Arc owners, other cache families and unbounded notification data queues remain separate coverage. A process-wide lease attached only to the cache wrapper would be insufficient because an external BlockTransactionsV3 owner can outlive cache eviction; that ownership redesign and cold-decode admission are explicitly deferred.
