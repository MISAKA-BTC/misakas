# MisakaOption経済仕様MOE1の適用・移行

- 日付: 2026-11-20（Asia/Tokyo）
- 状態: **ADOPTED_DESIGN_NOT_ACTIVATED**
- 正本: [RFC0063](../rfc/0063-additional-model-option-economics.md)、[ADR0231](../adr/0231-additional-model-option-economics.md)、[RFC-v2-0011](../rfc-v2/0011-bond-budgets-fees-and-payments.md)
- 前提: [TB1/FOW1](palw-tb1-fow1-transition.md)の正当性、乱数、採掘適格性、元claim、全検証・Court条件を維持する。

## 1. 対象と現在の状態

MOE1は、対象worker報酬の配分、追加モデルのMisakaOption/ModelPosition、通常AMM手数料、直接送受信と承認、移行条件を一体として定義する後続採択である。既存networkの支払・ABI・合意状態が文書変更だけで切り替わったとはしない。

genesisおよび有効な年次softforkカタログで指定されたモデルは、native正本から`GENESIS`又は`FORK_DESIGNATED`として解決する。それ以外の対象登録を`ADDITIONAL`とする。名称、登録者の申告、重みが派生版であること、単独の係数値から自由に分類を選ばせない。

## 2. 登録と市場の同時作成

**追加モデルの登録と、その不変model registration IDに対応する一意な市場の作成は、同一の原子的状態遷移で行う。**

\[
\mathrm{ModelRegistered}(m)\land\mathrm{Kind}(m)=\mathrm{ADDITIONAL}
\quad\Longrightarrow\quad \exists!\,\mathrm{Market}(m).
\]

登録record、market identity、曲線版、Position inventory、virtual/real reserve、retired量等の初期状態を同時に確定する。失敗時は両方を反映しない。通常状態として「登録済み・市場未作成」「後でseedを集めて市場を作る」「別市場作成取引を待つ」を設けない。外部seed/deepenを使用する場合は、存在する市場への任意の流動性増強である。

genesis・softfork指定モデルの登録は市場を生成しない。通常のlive状態で追加モデルの市場が欠けている場合は、状態不整合又は不正transitionとして扱う。買上げを省いてMinerへ100%を払う報酬分岐にしない。修復・IBD・migrationもこの不変条件を確認する。

市場が存在することは、モデルの正当性、FOW1の費用定理、任意数量の売却に十分なreal reserve、採掘資格を証明しない。virtual reserveは払い出せるBILIではない。通常売却のreal-reserve制約は維持する。

## 3. モデル種別ごとのworker報酬

Rは、当該モデルに帰属する認証済みclaimについて、適用される計算量価格付け・tier・共通報酬上限処理後の対象worker報酬である。ネットワーク全報酬、別のservice escrow、取引手数料を混ぜない。

| 種別 | Option市場 | Rからの買上げ | Rの帰属 |
| --- | --- | --- | --- |
| GENESIS | 作成・有効化しない | 0 | Minerに100%。Panel、owner、prefix worker等をRから控除しない |
| FORK_DESIGNATED | 作成・有効化しない | 0 | Minerに100%。同上 |
| ADDITIONAL | 登録時に一意に作成 | floor(500R/1000) | 残額をそのclaimの版付きProducer/Panel等の規則で配分 |

coreモデルでも完全検証・資料供給・Courtを維持する。必要な役務費は独立した事前確保原資、署名済み同意、有限予約・期限で賄う。資金不足なら新規義務を受け付けない。同じRを「別原資」と呼び直して控除したり、未確保の将来報酬を担保にしたりしない。

100%はRに対する権利配分であり、Final、成熟、vesting、責任hold、共通予算、export capの免除ではない。追加モデルのbuybackによるreserve流出も対応する共通上限へ合算する。

## 4. 手数料とPosition

通常のAMM買い・売りはgross BILI額Gについて、burn=floor(50G/1000)、owner総額=floor(30G/1000)、net=G−burn−ownerとする。owner総額には既存contributor内部配分も含め、合計を3%より増やさない。売却ではreal reserveから減るgrossと、受取net・feeの合計を一致させる。

自動buybackは買上げ原資の全額を当該reserveへ投入し、追加BILI burnもowner直接支払も0とする。取得Positionのretirementは、BILIのburnとは別の状態更新である。価格上昇・収益を保証する制度とは記述しない。

直接送金・受取・譲渡・approve・allowance・transferFromを追加モデルで許可する。直接移転にAMMの5%＋3%を課さず、通常のnetwork fee/gasだけを扱う。外部の相対売買による移転にAMM手数料が発生しないことは、この適用範囲の帰結である。

native/EVMは一つの残高・allowance正本を使う。新transferは同一transaction内のjournalで残高・allowance・logを原子的に扱い、revertで全て戻す。旧非同期queueへの受付をTransfer成功と表示しない。holderの移転でmodel owner、管理鍵、bond、claim、ExecCredit、過去責任を移さない。membershipの新しい判定は認証された受取人残高とtier時計に従う。

## 5. 旧規則の置換

| 旧箇所 | MOE1で適用する規則 |
| --- | --- |
| ADR0087、0095、0101の非譲渡・curve限定 | 追加モデルの直接送受信・承認を許可。サービス権・責任は別規則 |
| ADR0089のtransfer拒否・EOA限定・全write非同期 | 新同期transfer/approve経路をnative journalへ結合。旧AMM queueとは区別 |
| ADR0091の5%買上げ・市場なし全額fallback | 追加モデル50%、core0%＋Miner100%。追加登録時の市場作成を不変条件化 |
| ADR0114のowner5% | 通常AMM owner総額3%、burn5%、net残差 |
| ADR0124の全モデル共通Panel pool | additional残余への版付き分配だけ。core RからのPanel控除なし |
| ADR0177のowner5%・報酬5% | owner3%、追加のみ50%買上げ。共通資本・発行上限は維持 |
| ADR0179の階層・Position範囲 | native分類を使用。genesis/年次softforkは市場なし・Miner100% |
| ADR0090/0094/0162の旧seed待ち・core sell-only | 新追加登録は市場同時作成。core旧市場をlive fallbackへ継承しない |
| RFC-v2-0011・ADR-v2-0021/0023 | 現行本文をMOE1へ改訂。埋込原条文は当時の記録として保持 |

## 6. activationと旧責任

MOE1の対象network、署名・ABI・state版、有限な有効化位置を別の明示recordで決定する。claimは受理時のEconomicPolicy、モデル分類、owner/beneficiary、原期限等を認証snapshotへ束縛する。通常売買・移転は実行時の有効な取引規則とnative分類を使用する。途中で旧claimの率を読み替えたり、Final時に都合のよい分類へ付け替えたりしない。

旧claimは元条件で終結させる。coreに旧市場・残高・allowance・未決済義務が存在する場合は、没収しない明示的なwinddownと権利保全を有効化前に完了する。追加モデルをcoreへ指定する変更も同じ条件を満たす。手順未確定・未完了なら当該変更を有効化せず、恒久的なcore sell-only市場を新規則の例外にしない。

登録と市場の原子的初期化、同期EVM transfer、全資金源、同一状態検査、二重払拒否、reorg/restart/IBD、tier時計、旧残高移行を実装・検証するまで未有効化とする。TB1/FOW1の未完了gateを経済比率の変更で免除しない。
