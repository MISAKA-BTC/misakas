# 公開資料・モデル未保有Panel — 独立レビュー基準

対象はユーザーが明示採択した公開資料、少なくとも一人の正直な選出者、モデル事前保有不要、最低1件の完全検証承認、局所court、有限な資料要求・係争・容量である。本基準をレビュー結果に合わせて弱めない。

## 固定する判定条件

1. 新profileの保証は、各claimを担当する独立選出集合に、能動的に全体を検証する正直な参加者が一人いるという条件付きである。global poolのどこかに一人いること、未知の正直さをNodeが測定できること、縮小した任意部分集合にも一人いることを仮定へ混入しない。
2. モデルの事前保有・Minerの推薦・所有者の許可・取得に成功した者だけへの再選出を、検証資格にしない。公開対象にはpromptに加えて重み、構造、program、tokenizer、token列、数値規則、KV等の依存、RNG、初回traceと認証を含む。
3. originalとmanifest、全実行関係、演算位置・型・read/write・数値意味・停止・出力・仕事会計のbindingを保持する。Nodeはモデル全量・全推論・新proof VMを使わず、有界な元資料とnative checkerで裁く。
4. 最低完全承認数1は新profileだけの規範とする。1署名で即Final、旧75/41の遡及変更、全Panelの追加ACK要求、局所positiveの全体承認化を認めない。
5. モデルを持たない正直な選出者の資料要求には、完成算術反証や別人の票を要求しない。未解決caseは多数承認で消えず、供給後InspectionPendingへ継続する。B1〜B5の保護を維持する。
6. 虚偽の資料要求・計算異議・不署名への対処を定義する。packet不正とcase終了を区別し、客観的前提のないChallengerDefault、quota消尽による検証完了、他人のcase終了による救済消去を許さない。
7. 正常完了の保証は、正しいMiner、実供給、全合法caseを有界に客観終結できるprofile別手順、包含・資源・期限が成立する場合に限定する。公開URLや一部chunkから全資料の取得完了を推定しない。その手順が具体化されていないprofileは活性未確立・有効化不可と明記し、要件を書くことを完成の証拠にしない。
8. cold取得・全再実行・局所化・証拠作成・包含・裁定・回復を原時計内で予約する。最後の適格noticeの全合法工程も収容する。全選出者の有限な個別救済枠を、共謀者の先着要求で消費させない。
9. batchは版付きの任意最適化で、封印後抽選・固定scope・全leaf検証・全仕事量と価値の合算・二重計上拒否を定義する。今回のatomic方式では、既受理originalの吸収、後付けleaf、部分credit、1leaf反証後の残りの成功を認めない。
10. 旧54認証/日、EXEC1 BPS、抽選位置数、claim数、実検証主体数、再実行・配信・court容量を混同しない。未測定の新m、帯域、tile幅、期限、処理量を確定値として記載しない。
11. 初期モデル一つについてcold唯一正直、正常Final、反証、不供給Abort、遅延供給、悪意多数不署名・最大虚偽case、restart/reorg/IBD、同batchの取消と消費を要求する。toyモデルを実LLM・native実装・実資源測定の代替にしない。
12. 旧署名・旧記録・歴史付録・既存経済値・20冊/50冊・全Nodeの軽さ・計算暗号証明不採用を維持する。既存報酬式の不整合・bootstrap・全関係checkerの未確定事項を隠さない。

## 判定

- **FAIL / BLOCKER**: 上記に反する経路、相反する同scopeの規範、保証の過大表示、または必要な状態分岐の未定義がある。修正して再レビューする。
- **CONDITIONAL SPEC PASS**: 明示した前提と未完gateの下で文書の規範が整合し、今回の範囲に未解決の重大な反例がない。実用可能なprofileが完成・採択条件を実証したという判定ではない。
- **PROFILE PROCEDURE / IMPLEMENTATION / MEASUREMENT NOT ESTABLISHED**: profile別の客観的供給・検査機会の成立手順、全LLM関係、native実装、最低要件機材の測定が未確立なら、この状態を個別に残す。全拒否だけで完成と扱わない。

執筆後に別エージェントがRFC16〜20と関連規範を確認し、指摘と修正、最終判定をREVIEW.mdへ記録する。履歴のFAILや既存監査エラーを削除して見かけの合格を作らない。
