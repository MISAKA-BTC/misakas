# PALW実行正当性 — 独立レビューの固定基準

対象: 2026-11-09のユーザー指示によるRFC-v2-0016〜0020とその接続規範。
本基準は最終レビュー前に固定する。指摘を合格扱いにするために要求・攻撃モデル・失敗分岐を弱めない。
証拠不足は未確認として残し、文書レビューを実装・測定・activationのPASSへ変換しない。

## 判定する主張

1. 固定されたモデル・program・入力・数値規則・依存からの実行正当性を対象とする。Miner本人や各Panelの物理的実行行為、実消費資源、全員共謀時の無条件な全体positiveを証明したとは主張しない。
2. 受理profileの全実行関係は原Minerの初回commitに結び付き、Init／全Step／Endの成立が正規の出力・停止・長さ・仕事会計を含意する。
3. 認証可能な資料を取得でき、偽の必須関係がある場合、Nodeの上限内で客観的に反証できる。Nodeはモデル全体・全推論・新しいproof VMを必要としない。
4. 一人の適格な検証者の期限内notice／資料要求／有効反証は、多数のpositive・veto閾値・他case棄却・予約枠占有によって消えない。
5. 計算反証はnativeの直接検査で無効化へ進む。資料不足、検証不足、サービス障害、私的timeout、偽の告発、計算不正の責任を混同しない。
6. 必要承認・局所計画・公開窓・依存・義務・資源条件がそろわないclaimは成功Final／成功仕事報酬／consensus creditに入らない。認証とFinalを循環させない。
7. deadline、同一canonical batch、hard+1、Final後責任窓、再起動・reorg・IBD、冪等性、credit取消を含む状態遷移が一意である。
8. 一人保証の配送・資料・包含・native正当性・有限予約の前提を列挙する。任意の永続検閲や無限outsiderを仮定から消さず、保証外を明記する。
9. 全拒否や未測定profileだけを「利用可能なPALW完成」の根拠にしない。実LLM・同一binary・最悪混合負荷・失敗経路の実行は有効化前の別gateとして残す。
10. 既存の署名版、20冊の現行構成、旧原文・歴史付録・証拠、モデル二階層、既存経済値、EXEC 1 BPSの意味、暗号計算証明の不採用を維持する。

## 判定方法

- **BLOCKER / FAIL**: 上の主張に反例がある、必要な論理分岐が未定義、相反する規範が同じscopeに適用される、または保証を過大表示している。仕様を修正し、独立に再レビューする。
- **CONDITIONAL SPEC PASS**: 明示した前提の下で主張が成立し、レビューで未解決の設計BLOCKERがない。これは全現実環境での安全性・完成コード・性能・本番有効化の証明ではない。
- **IMPLEMENTATION / MEASUREMENT NOT ESTABLISHED**: 添付がdocsであるため、Rust native実装、実LLMの局所化、最低要件機材の最悪測定、公開ネットワーク包含は未検証。規範で検証義務を定めることと、その成功を報告することを区別する。

少なくとも一回、本文修正後に独立エージェントが全対象を読む。BLOCKERが出たら修正後の同じ対象を再確認する。各roundの指摘、対応箇所、残余前提、最終判定をREVIEW.mdへ保存する。既存の入力時点の監査FAILは保全し、今回の差分回帰と分けて報告する。
