# PALW 公開モデル可用性 RFC

状態: 2026-11-10 ユーザー方針。規則の詳細は Draft、未実装・未有効化。上位方針は [原則 §9](../PRINCIPLES.md#9-モデルの二階層と公開取得可能性--2026-11-10-ユーザー決定)。既存の claim 検証・認証とモデル二階層を維持する。

## 目的と成功条件

モデルの共有を、独立した claim 検証の前提にする。成功 Final は、公開先・manifest の照合、期限内の可用性認証、未解決の適格な取得異議がないこと、既存の claim 検証と抽選検証者の承認のすべてを必要とする。公開を確認しても計算の正しさは判定できない。楽観的 Final や一致したローカル再実行は SecurityCertified を代替しない。

## 公開と identity

原則として Hugging Face の公開かつ非 gated の repository を使う。ログイン、承認、専用 token なしで、全重み・config・tokenizer その他実行と検証に必要な全ファイルを取得できること。登録情報はサービス、repository、固定された完全 revision、正規 manifest の root、各ファイルの相対 path、サイズ、SHA-256、合計サイズと、既存モデル ID／artifact root との binding を含む。path の重複、欠落、サイズ不一致、hash 不一致を拒否する。URL や revision の申告だけでは取得可能性を確認できない。

Hugging Face が使用できない場合、認証なしの公開取得、固定版と全ファイルの取得を満たす代替サービスを、ネットワーク共通の所定の governance 手続きで指定する。切替の発効点、停止判定、候補選定、異議、移行期限、既存 claim の扱いは実装・有効化前に確定する。代替先の全ファイルは同じ manifest と照合し、既存 identity を上書きしない。外部サービスの判断を各ノードが独自に合意ルールへ反映しない。

## 取得検査と異議

- 初回は独立検査者が全ファイルを実際に取得し、manifest とサイズ・hash を照合して署名付き結果を提出する。
- 運用中は事前に固定した chunk commitment に対し、予測不能な乱数で選んだ位置を独立検査者が取得・照合する。期限付き認証と定期的な全量再検査を設ける。サンプル成功は全量取得を保証しない。
- Panel の適格な失敗申告には対象 claim、モデル、取得先、ファイル、時刻と結果を記録し、成功 Final を保留する。独立取得者が再試行し、必要に応じ同じ manifest に照合された独立 provider から当該 Panel への配布を試みる。第三者が取得できたことだけでは Panel が取得できたと扱わない。
- 所定期限内に検証可能な状態または事前に定義された代替裁定条件が成立しなければ成功 Final にしない。429、障害や到達性の問題を直ちに不正や slash と認定しない。悪意ある申告による停止と正直な Panel の排除を完全に区別することはできない。

検査者の選出・独立性・正直な割合、必要承認数、証拠の署名・公開・検証、乱数、期限、費用・サイズ上限、失敗申告の適格性、異議の濫用対策、裁定と再試行、Final の失敗／保留状態、既存 claim の移行を、決定論的に実装できる仕様として有効化前に定める。未確定値を既存 consensus の事実としない。

## 限界と受入確認

外部サービス、検査者、通信経路に依存する。特定時点の取得成功や抜き取りは、世界中の利用者や選出 Panel 全員の将来の取得を保証しない。検査者の正直さと到達性の仮定を明記する。ハッシュと Merkle commitment はデータ同一性の照合に使う。

受入試験は、private・gated・認証要求、ファイル欠落・hash 不一致、初回未完了、認証期限切れ、異議中・期限超過、429 と一時障害、Panel だけの到達不能、虚偽申告、代替サービスへの移行と identity 一致、未認証 claim の拒否を含む。これらの試験を本 RFC の記載だけで成功済みとしない。
