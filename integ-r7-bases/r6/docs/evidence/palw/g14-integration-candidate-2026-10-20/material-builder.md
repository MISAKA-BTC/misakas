# ADR-0199 A borrowed authenticated material builder view

Parent `4dff68eab`. A detailed-specification/isolated-implementation approval exists; no production adoption follows.

## Runtime boundary

`SharedTirBuilderStoreV1` is an internal read-only evidence-store implementation. It resolves the retained original/shared scope, requires complete unforgeable authenticated source-unit capabilities from that exact source, rejects repeated query coordinates, and verifies unique ascending parameter openings against the actual registered program and original artifact root. Optional complete authenticated IDs must have the same source identity. Inputs remain borrowed from their existing owners; constructor validation gives no custody/availability/paid admission certificate.

The unchanged builder's step preimages and single-leaf openings come only from supplied StepLeaf material. Parameter single openings come only from the validated supplied subset; existing native default multiproof composition is reused. StepNode/RowsNode material can be read only when supplied. Tiled decode IDs can be projected only from a supplied complete authenticated ID capability. Prompt material and two-tile row-pin assembly are not implemented: those reads explicitly return None. No fixture execution, disk, network or arbitrary local cache is accessible to the store. Missing material is builder refusal, never conviction/default/payment.

## Range transformation

A builder may ask for a contiguous operand run that exceeds a single existing source StepRun unit. The view derives that run's canonical outer siblings from authenticated StepLeaf openings at its two endpoints. The new native capped helper validates both complete boundary openings against the same expected root, consumes both paths with the existing odd-promotion geometry, and emits only the required left/right range siblings. It reads no complete hash tree or interior leaves. The builder still reads/authenticates every actual operand preimage through its normal canonical evidence checker; range siblings alone certify no computation.

Tests compare every contiguous range at leaf counts 1 through 33 with the existing full-tree sibling builder, then check the assembled range root. Wrong root, inverted bounds, exceeded native cap, missing/extra path material refuse. The supplied native cap is never enlarged.

## Fixture construction and intended evidence

The existing public-original GQA test provisions authenticated StepLeaf units for the original's leaves. For each terminal, the unchanged direct builder acts as a test-only read-set oracle for the parameter subset; openings are obtained from the fixture and authenticated again by the new view. This is not an implementation of original-wide dependency discovery, paid prefetch or reservation. The view itself never receives the fixture execution/store.

For both honest and false numerical partition histories, the intended comparison is all twelve terminals each: native bottom construction through supplied authenticated material must equal direct construction byte-for-byte. Empty parameter material and empty step material must refuse with no fallback; wrong scope, duplicate or altered parameter inputs must refuse. Prompt/decode/two-tile row cases are not established by these terminals. Original registration/payment/service-book assumptions remain synthetic/verified-half.

## Unclosed work

This is a borrowed runtime view, not a persistent material store or public transaction handler. Source reconstruction, duplicate scans, returned clones, parameter multiproof/range assembly, full builder/output ownership, CPU/IO/invalid-ingress/retention and physical fee/capacity calibration remain explicit caller-admitted unfinished work. No caller-provided nominal budget is promoted to a real reservation. Native program/index validation uses its existing tickets, but those tickets do not cover every view/builder allocation.

Still required: prompt/row-pin material, actual original-wide input closure, bounded paid storage/holding and recovery, no-blocking multiblock material ingress, all legal branch reservations/funds, F02 opportunity/default/recovery, global local-fault responsibility and archive/settlement, T05/T01-T15/R-D2 and real-model door. No new lifecycle/key/row/tag, fee/limit/deadline, holding obligation, slash/credit, pre integration/push, arming or deployment is introduced here.

## Functional result

Fresh edge/range tests pass 2, public-original fold tests pass 42, and the same fresh executable's court/inventory tests pass 11. The existing history test was extended with all 24 byte-identical material-backed terminal rebuilds, missing-step/parameter refusals and constructor scope/duplicate/alteration refusals. Cases are not additional test counts. These fixture results do not establish full original-wide prefetch, prompt/row coverage, funded node ingress, F03/T05 or calibrated costs. Integration/type-check results are recorded separately after completion.

Fresh t12 identity (9) and activation (5) integration tests also pass, for 69 unique selected tests total. Existing native fixtures and production caps/deadlines/tags were unchanged. Documentation remains exit1 with five imported missing references and 43 baseline-known occurrences, and no authored missing link. Type-check exits are recorded in the final artifact.
