## 1. RFC-0009: PAV3 provider exchange in the shipping miner

- New `misaka/palw/remote/src/native_custody_exchange_v3.rs` (`pub mod` in `lib.rs`):
  - `ProviderExchangeV3` implements `attempt::NativeCustodyV3`:
    - `session` = `select_native_session_v3` over rows set by `set_rows` (authenticated op-242 view); `operator_of` answers only for
      configured providers whose key was proven at `--pin` (unknown providers count for nothing → never healthier than the chain).
    - `manifest`: asks every uncharged roster provider over `provider_transport_v1` (purpose `NativeReadyV3`, existing variant; no new
      tag), verifies the response signature under the proven key, requires responder == provider asked, root == session root, one
      scope, and identical manifests from all providers. Any miss → Err (nothing mounted).
    - `collect`: sends Ready + capture to each roster provider; each signature must pass `verify_ready_signature_v3` under the proven key.
    - `seal`: the bond key (`ValidatorKey::sign_with_context`).
  - Bodies `PalwNativeReadyRequestV3` / `PalwNativeReadyResponseV3` (the names the existing `NativeReadyV3` doc comment referred to but
    which did not exist). HTTP path `/palw/native-ready/v3` (`HttpProviderLinkV3` over `transport::transport_for`).
  - `parse_provider_flag_v3`, `decode_hex_v3`.
- `palw-remote-miner.rs`: flags `--native-provider <txid>:<index>=<url>=<pubkey hex|@file>` (repeatable, requires `--pin`) and
  `--native-max-body-mib`; each provider key proven with `proof::verify_bond_against_pin` at the pin (operator id from the proof);
  each step refreshes rows via `monetary_material_rpc::fetch_monetary_material_contracts_v1` at node 0's sink (failure → empty rows →
  fail closed) and passes `Some(exchange)` to `step_with_custody`. Without providers the behaviour is unchanged (`NativeCustodyRequired`).
- Tests (crate `misaka-palw-remote`, `cargo test -p misaka-palw-remote native_`; module `native_custody_exchange_v3::tests`):
  `native_exchange_fetches_one_agreed_manifest_from_every_roster_provider`,
  `native_exchange_refuses_disagreeing_unknown_or_foreign_manifests`,
  `native_exchange_refuses_a_response_not_signed_by_the_proven_key`,
  `native_exchange_collects_verified_ready_signatures_in_roster_order`,
  `native_provider_flag_parses_and_refuses_malformed_text`,
  `native_exchange_session_counts_only_proven_operators`.
- Uncertain: test fixtures build `PalwMonetaryMaterialRowV1` / `PalwAttemptUnsignedV2` by borsh-decoding the shortest all-zero buffer
  (helpers `row_zero_bytes`, `provider_zero_bytes`, `attempt`); if any field rejects zero (e.g. a validated enum/len) the fixture panics
  and must be replaced by explicit constructors. The pinned sink used for rows is node 0's sink: it is authenticated relative to that
  header by the pager, but the header's place on the verified chain is the quorum/L1 check, not re-checked here.
- **Not implemented: the provider-side HTTP server** for `/palw/native-ready/v3` (the provider's half,
  `native_ready_v3::provider_sign_native_ready_v3`, exists as a library fn). A real E2E needs a provider process serving it.
- Fence: none new; behaviour follows `palw_monetary_material_v1` (existing) via `custody_in_force`.

## 2. RFC-0002/0013: PALWQ361 long-sequence fit

- New bin `misaka/palw/base0/src/bin/qwen36-window-compare.rs`, modelled on `qwen25-window-compare`: integer engine advances the whole
  prefix on one cache; the f32 reference window logits come from a FILE (`misaka-palw/qwen36-reference-windows/v1`: u32 header len, JSON
  header binding `tokens_sha256`, `sequence_tokens`, `window_len`, `window_starts`, `vocab`, then f32 LE rows), because the 35B-A3B f32
  forward over 32K is not computable on this host. KL only with `--logit-scale` (PALWQ361 has no calibrated scale on record); `--control`
  prefix-cut comparison as in the A16 tool. Rust tests: `qwen36_reference_windows_bind_the_sequence_and_shape`,
  `qwen36_kl_refuses_a_missing_or_bad_scale` (`cargo test -p misaka-palw-base0 --bin qwen36-window-compare`).
- `scripts/genesis/genesis10_pipeline.py`: `fit_plan` for PALWQ361 returns True only when `--palwq36-artifact` and
  `--palwq36-reference-windows` are existing files; otherwise False with a reason (→ existing SystemExit before upload). New
  `Pipeline.fit_palwq36`, `palwq36_window_fit` (refuses missing logit scale / foreign sequence / missing windows / missing KL; same
  tolerance as A16 via `a16_window_fit`), preflight needs `qwen36-window-compare`. Flags `--palwq36-artifact`,
  `--palwq36-reference-windows`, `--palwq36-logit-scale`.
- Python tests (run, OK): `scripts/genesis/tests/test_genesis10_pipeline.py::Palwq36Windows` (4 tests); whole file 21 tests OK.
- Open: no tool here produces the reference-windows file (needs an f32 host for the MoE); and the PALWQ361 logit scale is a user/measurement
  decision. Until both exist the fit stays refused (no fake pass).
