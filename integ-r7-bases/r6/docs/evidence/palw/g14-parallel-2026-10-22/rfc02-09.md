### Gap closed: catalog key vs registered root
The genesis-8 catalog lists the **container** root, but `palw_model_tier_at_v1` matched the catalog with `class.artifact_root`
(the **inventory** root) — so a genesis TIR model would never be 1.0-tier. Fixed:
- NEW `consensus/core/src/palw_artifact_identity_v1.rs`: newtypes `PalwContainerRootV1`, `PalwInventoryRootV1`,
  `PalwArtifactDigestV1` (no `From<Hash64>`, zero refused by `named`); checked doors
  `palw_tir_inventory_of_container_v1` (container → inventory only through the single TIR-inventory section, A16-digest section
  refused), `palw_registered_inventory_root_v1` (only for a class with a TIR record), `palw_catalog_container_root_of_class_v1`
  (bound row, `bound_daa <= daa`).
- `consensus/core/src/palw_model_tier_v1.rs::palw_model_tier_at_v1`: if the registered-root read is not approved, retry with the
  bound container root. Dormant: the row exists only past `palw_tir_container_identity_v1`; otherwise byte-identical.
- `consensus/core/src/palw_genesis8_catalog_v1.rs`: `PalwGenesisRootsV1.artifact_root: Hash64` → `container_root:
  PalwContainerRootV1` (only in-file users); module doc's "open integration requirement" replaced by the path description.

Design note: the tier read accepts either the registered root (unchanged behaviour) or the bound container root; both identify the
same class (the binding is checked to commit the registered inventory). Within RFC-0019 tier rules + RFC-0002 02-A; no new fence.
